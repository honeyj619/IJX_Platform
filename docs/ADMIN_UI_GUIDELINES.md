# IJX Platform 管理后台设计规范

版本：1.0  
适用范围：`/admin` 下的管理后台页面  
设计基线：当前综合管理后台“版本管理”页面、现有后台组件与品牌约定

## 1. 事实来源与使用边界

- 本规范从当前系统保存页 `综合管理后台 _ 版本管理.html` 的应用 DOM 与本地 CSS 提炼；浏览器翻译插件等注入内容不属于系统规范。
- 当前系统是参考事实，原型可增加 Windows、macOS 等演示范围，但同类结构、状态和操作层级必须一致。
- 管理后台使用独立桌面端体系，不套用 `/pc_client` 的工作面骨架，也不套用员工端品牌粉色。
- 管理后台操作主色为 `#337AB7`；员工端品牌主色变化不得覆盖后台操作色。

## 2. 页面骨架

标准列表管理页按以下顺序组织：

```text
后台多页签栏
页面头部
├─ 面包屑
├─ 查询筛选区
└─ 对象分类 Tab（可选）
页面内容区
└─ 白色数据工作面
   ├─ 操作栏
   ├─ 数据表格
   └─ 分页
```

- 页面底色使用后台浅灰底，头部和数据工作面使用白色。
- 管理后台主内容区使用 `24px` 页面级内边距；不得使用 `32px`，也不得直接清零后让内容贴住后台壳层。
- 筛选区、Tab、列表等白色内容容器内部统一使用 `16px` 内边距；文字、表单和操作栏从容器内边距线开始对齐。
- 页面级 `24px` 与容器级 `16px` 必须分层实现，不得把二者合并到同一个元素，也不得用表格单元格 padding 代替容器内边距。
- 相邻白色内容容器之间保持 `16px` 间距。
- 不使用大圆角、重阴影和营销型卡片；后台层级主要依靠底色、边框和间距区分。

## 3. 查询与筛选组件

### 3.1 排列

- 桌面宽屏优先采用“四区一行”：三个筛选项 + 右侧操作区。
- 筛选项使用“标签 + 控件”横向排列，标签右对齐，控件占剩余宽度。
- 条件区水平沟槽为 `24px`；换行后保持 `8-12px` 垂直间距。
- 窄屏依次降为两列和一列，操作区跟随换行但保持按钮顺序。
- 标签较长时扩大标签列，不压缩输入内容；版本管理中普通标签基线 `96px`，“是否强制更新”可使用 `112px`。

### 3.2 控件

- 输入框、下拉框和按钮在同一区域保持相同高度，当前基线为 `36px`。
- 默认边框使用中性灰，聚焦描边使用 `#337AB7`，可配轻量同色 focus ring。
- 输入框 placeholder 使用“请输入 + 字段名”；下拉框 placeholder 使用“请选择 + 字段名/状态”。
- 下拉框存在“全部”语义时，内部值可以是“全部”，展示文案优先说明选择对象，例如“请选择状态”。

### 3.3 行为

- 筛选控件先保存草稿值，点击“查询”后才应用到列表；输入过程不应让大表格频繁跳动。
- 版本号等主要文本条件支持 Enter 触发查询。
- “重置”同时清空输入值、已应用条件和当前页码，恢复默认列表。
- 切换分类 Tab 后回到第 1 页。
- 只有确有隐藏条件时才显示“展开/收起”；没有额外条件时不显示无效入口。

## 4. 按钮规范

### 4.1 主要按钮

- 用于查询、新增、保存、确认等当前区域的主操作。
- 默认：背景和边框 `#337AB7`，文字白色。
- Hover：`#5695C4`。
- Active：`#215991`。
- Disabled：浅灰背景、灰色文字、不可点击光标。
- 同一操作区通常只保留一个视觉主按钮。

### 4.2 次要按钮

- 用于重置、取消、返回等操作。
- 白色背景、中性灰边框和正文色；Hover 使用浅灰背景或略深边框。
- 不与主按钮争夺视觉层级。

### 4.3 行内操作

- 编辑、下载二维码、查看等使用 `#337AB7` 文字链接。
- 多个操作之间使用稳定间距或竖向分隔线；高频操作直接展示，低频操作收进“更多”。
- 不可操作项保留位置并展示禁用态，必要时用 `title` 说明原因。例如已发布版本不可编辑。
- “更多”必须有实际菜单；原型未实现时明确提示“暂未开放”，不显示虚假成功。

## 5. 分类 Tab

- 用于 Android、iOS、Windows、macOS 等同类数据切换，不代替全局导航。
- Tab 与筛选区同属页面头部，底部使用分割线。
- 激活项文字加粗并使用 `#337AB7`，下方显示 `2px` 激活线。
- Tab 切换后筛选条件可保留，但分页回到第 1 页；同类页面必须采用一致策略。

## 6. 数据表格

### 6.1 表头与行

- 表头背景 `#FAFAFA`，标题文字中等字重，表头与数据行使用 `#F0F0F0` 级别分隔线。
- 当前系统紧凑表格单元格基线为水平/垂直 `8px`；内容较长的行可以增加垂直空间，但同表保持一致。
- 数据行 Hover 使用极浅中性色，不使用员工端品牌粉色。
- 无数据时在表格内部跨列显示空状态，不另起无关卡片。

### 6.2 列宽与溢出

版本管理参考列宽：

| 字段 | 参考宽度 |
| --- | --- |
| 版本号 | `80-96px` |
| 构建号 | `80-128px` |
| 是否强制更新 | `80-112px` |
| 状态 | `80-96px` |
| 修复内容 | `200-220px` |
| 描述 | `180-200px` |
| 更新人 | `80-96px` |
| 更新时间 | `160px` |
| 操作 | `160-220px` |

- 短字段不换行；长文本单行截断并通过 `title` 或详情方式查看全文。
- 表格宽度不足时只让表格容器横向滚动，不能压缩到字段不可读，也不能让整页产生横向滚动。
- 操作列保持稳定宽度，避免操作随内容跳动。

### 6.3 分页

- 统一复用 `src/components/admin/AdminPagination.tsx`。
- 分页位于表格右下方，展示总条数、上一页、页码和下一页。
- 筛选、重置、切换 Tab 或新增数据后，页码需要回到合理位置。
- 没有数据时不显示分页。

## 7. 表格式表单与弹窗

- 管理后台配置表单采用标签列 + 字段列的表格式对齐，标签区使用浅灰背景并右对齐。
- 同一弹窗内标签列宽固定；版本配置当前基线为 `128px`。
- 必填标识紧邻标签，保存失败时保留输入并给出明确提示。
- 弹窗头部、滚动内容区、底部操作区三段分离；内容过高时只滚动内容区。
- 底部操作右对齐，顺序为“取消”在前、“保存/确认”在后。
- 编辑已发布对象等受限行为在入口处禁用，不等用户填完后才报错。

## 8. 版本管理专项规则

- 筛选项至少包含版本号、状态、是否强制更新。
- 分类 Tab 至少区分 Android 与 iOS；原型增加 Windows、macOS 时沿用相同结构。
- 表格至少包含版本号、构建号、强制更新、状态、修复内容、描述、更新人、更新时间和操作。
- PC 客户端版本可增加安装包类型和支持系统，但只在相关平台展示。
- “版本列表”允许新增和编辑；“发布记录”只展示已经发布或失效的记录，不提供新增入口。
- 已发布版本不可直接编辑；需要变更时通过后续发布或明确的状态流程处理。
- 下载二维码、更多操作等原型反馈必须注明是模拟能力或暂未开放。

### 8.1 新增版本弹框（四端共用）

- Android、iOS、macOS、Windows 四个页签共用同一新增弹框组件（`src/components/admin/VersionCreateDialog.tsx`）；由当前页签决定新增记录所属端，弹框内不出现端类型选择器，也不能切换端。
- 端差异只允许出现在四项配置内：弹框标题（添加android/iOS/macOS/Windows版本）、安装包扩展名（.apk / .ipa / .dmg,.pkg / .exe,.msi）、列表安装包类型（APK / IPA / DMG/PKG / EXE/MSI）、默认系统说明（Android 10+ / iOS 15+ / macOS 12+ / Windows 10/11）。差异由 `versionCreatePlatformConfig` 统一驱动，禁止复制四份弹框 JSX。
- 字段顺序固定为：安装包、Logo、版本号、构建号、强制更新、适用范围、描述、修复内容；标签列沿用 128px 表格式对齐。
- 安装包必填：安装包扩展名校验不区分大小写，不依赖浏览器 `accept`；错误提示显示在字段下方，不用弹窗打断。
- Logo 必填：仅接受 PNG，且自然尺寸必须严格为 48 × 48 像素；错误文件不能进入有效表单状态；预览 object URL 在替换、关闭和组件销毁时释放。
- 版本号沿用现有非空校验（视觉上无红星），去除首尾空格，同端内版本号不可重复。
- 构建号只读，按 `YYYYMMDD + 当日三位序号` 生成（例如 `20261110001`），结合现有记录计算当日最大序号，禁止写死。
- 强制更新使用可访问的 Switch（`role="switch"`），默认"否"，保存布尔值；不使用普通 Checkbox。
- 适用范围为非必填单选，选项为"全员"加现有用户组，值使用稳定 ID。
- 弹框约 800px 宽（小视口下为 `calc(100vw - 32px)`），Header / 可滚动 Body / Footer 三段结构；低视口下只滚动 Body，标题与底部按钮保持可见。取消、关闭图标、遮罩和 Esc 走同一关闭函数并重置状态。
- 校验失败保留输入并聚焦第一个错误字段；提交成功后在当前端列表顶部新增"草稿"记录、回到第一页，并显示"XX版本已添加"轻提示。
- 原型阶段不接真实上传服务：安装包与 Logo 仅保存文件名、大小、扩展名等元数据，不把 `File` 对象或 Base64 写入长期记录，不伪造下载地址。

## 9. 验证清单

- 查询按钮实际应用筛选，重置恢复全部数据。
- 版本号输入支持 Enter 查询。
- 平台 Tab 切换正确，页码回到第 1 页。
- 空结果在表格内部正确展示。
- 分页根据筛选结果工作，不显示无效页码。
- 长文本不撑坏列宽，并能查看完整内容。
- 已发布版本的编辑入口为禁用态。
- 新增/编辑弹窗使用表格式对齐，必填校验有效。
- 主要按钮、分页和行内操作使用 `#337AB7` 体系。
- 1440px、1280px、1024px 下筛选区、表格和弹窗可读可操作。
- 完成后通过类型检查、生产构建和 `/admin` 页面交互回归。
