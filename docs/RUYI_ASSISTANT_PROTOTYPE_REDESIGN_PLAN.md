# 如意助手与如意空间 V1–V2 原型改造方案

> 文档状态：产品原型改造方案  
> 版本规划：V1（2026 年 12 月）/ V2（2027 年 3 月）  
> 当前实施范围：PC Client 前端原型  
> 依据：`V1–V2 产品功能总体规划`、项目 `Agents.md`、`MEMORY.md`、`docs/UI_DESIGN_GUIDELINES.md`、`docs/PROTOTYPE_REQUIREMENTS.md`  
> 后端需求：见 `docs/RUYI_ASSISTANT_BACKEND_REQUIREMENTS.md`

## 1. 改造目标

本次改造不把如意助手扩展成一套新的后端 Agent 平台，而是基于当前纯前端原型统一产品体验，解决以下问题：

- 如意助手、如意空间、PC 消息中的如意助手入口和体验不统一。
- 用户需要先理解并选择智能体，才能判断应该从哪里开始。
- 历史对话、专业工作台和生成成果之间缺少可见关联。
- 公文、PPT、汇报等专业能力各自形成独立流程，结果不易找回。
- 当前原型对“恢复对话”和“恢复任务”的区别表达不清。

改造后的产品定位：

- **如意助手**是统一交互身份。用户可以直接描述工作需求，不需要先选择智能体。
- **专业智能体/能力**是如意助手内部调用的专业能力，同时保留快捷入口帮助用户发现。
- **如意空间**是 PC 端承载统一对话、历史记录、专业工作台入口以及后续任务、成果管理的工作空间。
- **专业工作台**继续负责公文、PPT、汇报等结构化编辑，不被聊天页替代。
- **PC 消息中的如意助手**继续保留 IM 式快速对话，并与如意空间形成一致的产品语义。

## 2. 版本边界

| 产品模块 | V1 · 2026 年 12 月 | V2 · 2027 年 3 月 |
| --- | --- | --- |
| 如意助手主页 | 统一入口、统一输入、快捷能力 | 个性化快捷操作 |
| 智能对话 | 整合已有问答与专业能力 | 连续任务交互、业务结果卡片 |
| 会话管理 | 新建、查看、重命名、删除、刷新保留 | 搜索、筛选、任务与成果关联、跨端一致 |
| 智能体协同 | 统一唤起、显示当前能力、进入工作台 | 上下文传递、过程状态和结果回流 |
| 任务模式 | 单任务补参与恢复 POC，不设任务中心 | 多任务、确认、取消、恢复和任务中心 |
| 结果管理 | 统一成果卡片和基础关联入口 | “我的 AI 成果”统一索引 |
| 如意空间 | 统一对话、能力、历史入口 | 对话、AI 任务、AI 成果三类工作视图 |
| 多端体验 | PC 原型统一语义；App 本轮不改 | PC/Web/App 跨端查看和继续任务 |
| AI 质量 | 有用/没用、重新生成等基础反馈 | 场景评测、失败闭环和运营分析入口 |

### 2.1 V1 优先级

V1 必须优先完成：

1. 统一入口和统一对话体验。
2. 自有会话列表及基础管理原型。
3. 专业能力统一调用与展示。
4. 成果卡片和会话返回链路。
5. 单任务补参/恢复的有限 POC。

V1 不因新增专业智能体而推迟以上基础能力。

### 2.2 V2 聚焦范围

V2 只聚焦：

1. 多轮任务模式。
2. AI 任务中心。
3. 我的 AI 成果。
4. 初步跨端上下文与持续协同。

不在 V2 中继续扩散桌面控制、屏幕读取或完整 Agent 平台管理能力。

## 3. 信息架构与入口整合

### 3.1 规范入口

| 入口 | 定位 | 原型行为 |
| --- | --- | --- |
| `/pc_client/ruyi-zone` | 如意助手/如意空间统一主入口 | 展示统一对话主页或最近会话 |
| `/pc_client/ruyi-zone/conversations/:conversationId` | 历史会话 | 查看并继续指定会话 |
| `/pc_client/ruyi-zone/document` | 公文工作台 | 保留现有专业工作台 |
| `/pc_client/ruyi-zone/presentation` | PPT 工作台 | 保留现有专业工作台 |
| `/pc_client/ruyi-zone/advisor` | 参谋师工作台 | 保留现有专业工作台 |
| `/pc_client/ruyi-zone/tasks` | V2 AI 任务中心 | V1 不创建入口，V2 启用 |
| `/pc_client/ruyi-zone/results` | V2 我的 AI 成果 | V1 不创建入口，V2 启用 |
| `/pc_client/assistant` | 历史兼容地址 | 重定向到 `/pc_client/ruyi-zone`，不再维护独立静态页面 |

### 3.2 PC 消息中的如意助手

- 如意助手继续作为 PC 消息列表中的系统会话。
- 消息页保持三块布局和 IM 式体验，不在消息中复制完整如意空间页面。
- 简单问答、查询结果和确认回执在消息中直接展示。
- 内容创作和复杂工作流提供“前往如意空间/专业工作台”入口。
- 在同一 PC 原型内，PC 消息和如意空间复用同一份 mock 会话主数据，避免两套互相矛盾的历史记录。
- App 消息正在独立开发，本轮不修改 `/app/messages` 及其数据结构。

### 3.3 页面结构

如意空间继续遵循客户端“全局导航 + 单一主工作面”骨架，主工作面内部划分：

- 左侧功能栏：新建对话、快捷能力、历史会话。
- 右侧内容区：统一对话主页或当前会话。
- 专业工作台打开后使用既有统一工作台骨架，不在右侧对话区内继续嵌套复杂编辑器卡片。

V2 在左侧功能栏增加“AI 任务”和“AI 成果”，仍属于同一主工作面，不新增重复一级导航。

## 4. V1 原型改造

### 4.1 统一主页与新建对话

#### 首屏内容

- 标题：`你好，有什么工作需要我帮忙？`
- 说明：`可以查询信息、办理协同事项，也可以创作公文、PPT 和汇报。`
- 主输入框：`描述你的工作需求，或者添加参考文件…`
- 快捷能力：查询工作信息、如意公文、如意 PPT、如意参谋、智能翻译、IT 服务。

#### 交互规则

- 用户无需选择智能体即可输入并发送需求。
- 点击快捷能力只负责帮助发现和进入场景：
  - 即时问答/处理能力在当前会话预填引导语或激活能力标签。
  - 内容创作能力可以先收集需求，再进入专业工作台。
- 激活专业能力后，在输入框上方显示当前能力标签和退出操作。
- 选择专业能力后不展示通用“猜你想问”。
- 退出专业能力后回到普通对话，不删除当前会话。
- 用户每次发送、确认、修改、取消、打开成果等操作均生成新的对话消息，不在旧消息中嵌套推进流程。

### 4.2 统一会话管理

#### 会话列表

- 展示当前 mock 用户本人会话，按最近更新时间倒序。
- 列表项展示会话标题、最近消息摘要、更新时间。
- 来自专业能力的会话用辅助文字显示能力名称，不用能力名称替代会话标题。
- 当前会话有清晰选中态。

#### 新建会话

- 点击“新建对话”创建空白会话并进入统一主页。
- 新建会话不删除或覆盖旧会话。
- 第一条用户消息发送后自动生成会话标题。

#### 重命名

- 会话更多菜单提供“重命名”。
- 使用小型弹框编辑；空标题不可保存。
- 保存后列表与会话头同步更新并显示 Toast。

#### 删除

- 会话更多菜单提供“删除会话”。
- 删除前二次确认，明确说明：删除聊天记录不会删除已经保存的公文、PPT 或汇报成果。
- 删除当前会话后进入新建对话主页。
- V1 原型不提供恢复删除功能。

#### 持久化与隔离演示

- 会话、消息、标题和更新时间保存到 localStorage，刷新后仍存在。
- localStorage 数据以 `MAIN_USER_NAME` 对应的稳定用户标识分区。
- 演示切换用户时不得展示另一用户的会话记录。
- V1 不迁移现有硬编码历史；将其转换为默认种子数据，仅在首次初始化时写入。

#### V1 暂不实现

- 会话关键词搜索。
- 按日期、能力筛选。
- 真实 ADP 会话迁移。
- 真实企业留存策略。
- App 跨端同步。

### 4.3 专业能力统一调用

按交互形态而非页面数量组织能力：

| 类型 | 当前能力 | V1 原型行为 |
| --- | --- | --- |
| 即时问答型 | 通用问答、IT 服务、知识咨询 | 当前会话直接回复，提供来源或下一步入口 |
| 即时处理型 | 简短翻译、考勤/运营/待办查询 | 当前会话展示结果摘要和业务详情链接 |
| 内容创作型 | 公文、PPT、工作及项目汇报 | 对话确认需求，跳转专业工作台，结果回流原会话 |
| 业务执行型 | 创建日程、项目立项、提交反馈 | 对话补充参数，确认后展示模拟执行结果 |

#### 统一调用状态

每次专业能力调用需支持以下展示状态：

- 已识别：`已为你切换到如意公文能力`。
- 补充信息：明确缺少的必要信息。
- 处理中：展示简洁加载状态，不暴露模型或接口技术细节。
- 需要确认：展示参数摘要，并通过新消息完成确认/修改/取消。
- 已完成：显示结果摘要、来源和可继续操作。
- 失败：说明用户可理解的原因，提供重试、重新输入或前往业务页面。

#### 能力契约

每项首批能力在 mock 数据中统一声明：

- 名称和说明。
- 快捷入口文案。
- 支持的输入类型。
- 对话返回形式。
- 是否进入专业工作台。
- 是否产生工作成果。
- 成功、失败及失效示例。

原型不定义真实 API 或模型调用协议。

### 4.4 现有能力迁移

#### 查询型

- 待办/待审批：展示数量、简明列表和流程详情入口。
- 考勤：展示统计摘要、制度来源和详情入口。
- 企业知识：展示文字结果、来源文档和打开入口。
- 运营数据：Web 端以文字摘要和业务看板链接为主，不复制 IM 多卡片布局。

#### 事务型

- 创建日程：显示已识别参数、缺失项、确认消息和模拟创建结果。
- 项目立项：Web 端使用文字说明和流程页面跳转，不在对话中嵌入完整申请表单。
- 产品反馈/IT 服务：继续使用现有反馈能力，但提交、成功和查看详情均形成新消息。

#### 内容生产型

- 公文：需求确认后进入公文工作台；返回时在来源会话追加成果消息。
- PPT：需求确认后进入 PPT 工作台；返回时在来源会话追加成果消息。
- 参谋师：普通咨询可在对话中回答；生成项目周报等结构化任务进入参谋师工作台。
- 简短翻译在当前会话完成，不强制打开独立工作台。

### 4.5 基础成果关联

#### 回答结果与工作成果

- 回答结果属于对话消息，例如考勤余额、知识问答、操作说明。
- 工作成果是可以再次打开或继续编辑的独立内容，例如公文、PPT、项目汇报。

#### 统一成果卡片

成果卡片展示：

- 成果名称。
- 成果类型。
- 来源专业能力。
- 当前状态：可编辑、已完成、已失效、无权限。
- 主操作：打开成果。
- 次操作：查看来源会话；当前已在来源会话时不重复展示。

#### V1 边界

- V1 只统一成果记录和入口，不建设成果中心。
- 成果源文件、编辑和版本仍由公文、PPT、汇报工作台负责。
- 删除会话不联动删除成果。
- 成果失效时保留记录并展示原因，打开操作禁用。

### 4.6 单任务补参/恢复 POC

V1 仅选择“创建会议/日程”作为任务模式 POC，不扩展到全部能力。

#### 演示流程

1. 用户输入“帮我创建明天的会议”。
2. 助手识别已知信息并追问时间、参会人等缺失项。
3. 用户连续补充参数，页面持续展示已收集信息。
4. 用户临时询问“我还有多少年假”，助手先回答查询。
5. 对话中保留“继续创建会议”提示。
6. 用户继续后恢复已填写参数。
7. 展示最终确认消息；确认后生成模拟完成结果。

#### V1 限制

- 一个会话同时只保留一个可续接任务。
- 不建设任务列表和任务详情页。
- 不演示两个任务并行或歧义选择。
- 不演示跨端恢复。
- 任务状态仅用于产品交互验证，不模拟真实后台运行。

### 4.7 AI 质量反馈

- 助手回复保留“有用/没用、复制、重新生成”。
- 点击操作必须生成可见反馈；重新生成属于新回复，不覆盖旧回复。
- “没用”可展示原因选择弹框：答非所问、信息不准确、操作失败、其他。
- V1 仅前端记录反馈状态，不建设运营后台。

## 5. V2 原型改造

### 5.1 多轮任务模式

任务原型需演示：

- 发起任务并识别已知/缺失参数。
- 连续补参，不丢失之前信息。
- 临时切换话题后保留原任务。
- 通过“继续刚才的任务”恢复。
- 修改参数后重新展示确认摘要。
- 确认前允许取消；取消后不产生业务结果。
- 多个待续任务存在时，歧义场景要求用户选择，不自动决定。
- 执行失败时显示明确状态，避免盲目重复提交。
- 已完成任务不直接重放；后续修改应创建新的业务操作。

日期敏感任务跨日恢复时，原型必须重新确认相对日期的实际日期。

### 5.2 AI 任务中心

#### 页面定位

AI 任务中心只管理“如意助手正在帮助用户处理的 AI 任务”，不复制工作门户事项、项目任务、日程或审批中心。

#### 列表分类

- 待我处理：待补参、待确认。
- 执行中。
- 已完成。
- 全部。

#### 任务列表项

- 任务名称和简要目标。
- 状态和状态说明。
- 来源会话/入口。
- 最近更新时间。
- 相关成果或业务结果摘要。

#### 任务详情

- 任务目标。
- 已收集参数。
- 当前状态和需要用户完成的下一步。
- 来源会话。
- 结果或成果。
- 继续任务、取消任务、返回来源会话等操作。

所有操作形成新的任务状态记录和对应对话消息。

### 5.3 我的 AI 成果

#### 页面定位

成果中心是专业 AI 产品成果的统一索引，不是企业网盘，也不接管源文件编辑和版本管理。

#### 分类与信息

- 类型：公文、PPT、汇报、翻译及后续扩展类型。
- 信息：标题、类型、创建时间、来源能力、业务状态。
- 操作：打开成果、查看来源会话、查看关联任务。

#### 状态处理

- 可用：进入原专业工作台或查看页。
- 已失效：显示源文件已删除或链接失效。
- 无权限：展示无访问权限，不泄露内容。
- 来源会话已删除：成果仍保留，但来源会话入口禁用并说明原因。

### 5.4 初步跨端协同

V2 产品目标包括：

- PC/Web/App 查看同一任务状态。
- 在另一端继续补参或确认。
- 业务页面打开如意助手时携带当前业务对象摘要。

当前 PC 前端原型只需要：

- 定义并演示“来源端”和“最后操作端”字段。
- 在任务详情展示“可在 App 继续”的产品状态示例。
- 展示当前引用的业务对象标签及取消引用操作。
- 不修改当前 App 页面，不伪造真实跨端同步。

业务上下文切换页面后不继续自动沿用；重新使用时需再次明确关联。

## 6. 前端原型数据与状态

### 6.1 建议公共类型

原型需要统一以下前端 mock 数据对象：

- `RuyiCapability`：能力信息及交互类型。
- `RuyiConversation`：会话标题、用户、更新时间、当前能力。
- `RuyiMessage`：用户/助手/系统消息及展示状态。
- `RuyiResultReference`：成果索引、状态和工作台入口。
- `RuyiTaskMock`：V1 POC 或 V2 任务状态、参数和来源。
- `RuyiContextReference`：V2 当前业务对象摘要。

这些对象仅用于前端原型，不等同后端正式接口。

### 6.2 状态覆盖

mock 数据必须覆盖：

- 空会话和首次使用。
- 普通对话和专业能力对话。
- 自动标题和手动重命名。
- 删除确认。
- 加载、处理中、完成和失败。
- 待补参、待确认、已取消。
- 可用成果、失效成果和无权限成果。
- 单任务中断和恢复。
- V2 多任务歧义选择。

### 6.3 持久化

- PC 原型会话、V1 POC 任务和成果索引使用 Zustand + localStorage 持久化。
- 初始化数据只在当前用户无数据时写入。
- 提供原型数据重置能力，便于重复验收。
- 不保存真实附件内容、隐私数据或凭据。

## 7. Harness 约束

### 7.1 视觉与布局

- 使用 `#B82971` 对应的语义主题类，不新增相近品牌粉色。
- 如意空间保持全局导航和单一主工作面两块结构。
- 主工作面内部侧栏与内容区用分割线衔接，不增加多余底面间隙。
- 不使用营销式大标题、强渐变、霓虹、过重阴影和无意义装饰。
- 对话头和输入区固定，消息区独立滚动。
- 最小宽度 1024px，低于该宽度由最外层横向滚动，不切换移动布局。
- 公文、PPT、参谋师工作台沿用现有统一工作台规范。

### 7.2 对话交互

- 对话框固定在内容区底部。
- 助手回复使用统一消息样式。
- 每次用户操作形成新消息，不在旧消息内部继续推进。
- 专业能力激活后隐藏通用“猜你想问”。
- 删除、覆盖、重新生成、取消任务等操作需要确认。
- 加载、失败、空状态和完成状态都要给出下一步操作。

### 7.3 演示数据

- 主用户统一使用 `MAIN_USER_NAME` 和 `MAIN_USER_AVATAR`。
- 其他人员复用 `getDemoPerson()` 或现有演示人员数据。
- 不新增真实个人信息。
- 多页面复用能力、会话、任务和成果数据，不在页面中重复硬编码。

### 7.4 需求模式

- 实施阶段将稳定的功能规则写入 `docs/PROTOTYPE_REQUIREMENTS.md`。
- 如意空间首页、会话管理、成果关联、V1 任务 POC、V2 任务中心和成果中心分别维护连续序号。
- `data-requirement-id` 绑定常驻页面区域或弹框根节点，不绑定易消失按钮。
- 视觉细节留在 UI 规范和实现方案中，不写入需求模式。

## 8. 明确不做

本原型方案不包含：

- 真实模型推理、意图识别或 Agent 调度。
- 真实 ADP 会话迁移和映射。
- 真实 MCP、企业接口、凭据和权限校验。
- 真实后台异步任务和跨端同步。
- 完整 Agent Team 或 Agent 平台管理。
- 统一迁移公文、PPT、汇报的源文件。
- 用 AI 任务中心替代事项、项目、日程或审批业务系统。
- 跨应用桌面控制、屏幕读取和远程操作。
- 本轮 App 页面与 `/app/messages` 改造。

以上能力的真实系统需求以 `docs/RUYI_ASSISTANT_BACKEND_REQUIREMENTS.md` 为准。

## 9. 实施顺序

### 阶段 1：V1 统一入口与会话

- 合并独立如意助手入口。
- 改造统一主页、快捷能力和普通对话。
- 建立会话列表、新建、重命名、删除和持久化。
- 让 PC 消息与如意空间复用会话 mock 主数据。

### 阶段 2：V1 能力与成果

- 按四类交互统一迁移现有能力。
- 补齐识别、补参、处理、确认、完成和失败状态。
- 公文、PPT、参谋师打通来源会话和返回结果。
- 增加统一成果卡片、失效和无权限状态。

### 阶段 3：V1 任务 POC 与质量反馈

- 完成单个会议/日程任务的补参、中断和恢复演示。
- 增加回复反馈、重新生成和异常重试状态。
- 完成 V1 全链路验收。

### 阶段 4：V2 任务与成果

- 增加多任务上下文和歧义选择。
- 增加 AI 任务中心及任务详情。
- 增加我的 AI 成果。
- 增加跨端状态和业务上下文的展示原型。

## 10. 验收标准

### 10.1 V1 验收

- 用户无需选择智能体即可发起需求。
- 快捷能力可以进入正确交互形态，且明确显示当前使用的能力。
- 同一用户可以新建、查看、重命名和删除多个会话。
- 刷新后会话、标题和消息仍存在；其他用户看不到当前用户历史。
- 删除会话不会删除已经保存的成果索引。
- 简单问答留在当前会话；内容创作进入正确工作台。
- 工作台返回后，来源会话展示统一成果卡片并可再次打开。
- 查询、事务、内容生产能力均覆盖完成和失败状态。
- 会议/日程 POC 可以补参、临时切换话题并恢复。
- `/pc_client/assistant` 不再出现另一套静态助手体验。

### 10.2 V2 验收

- 多个未完成任务存在时，系统能在歧义场景要求用户选择。
- 任务可以补参、确认、取消、失败重试和完成。
- AI 任务中心不混入普通事项、项目任务和审批记录。
- 任务详情可返回来源会话并查看相关结果。
- 我的 AI 成果统一展示公文、PPT、汇报等索引。
- 成果失效、无权限、来源会话删除状态表达正确。
- PC 原型清晰展示跨端任务状态，但不伪装真实同步已经发生。

### 10.3 工程验证

实施每个阶段后至少完成：

- `npm.cmd run check`
- `npm.cmd run build`
- `git diff --check`
- 1440、1280、1024 宽度页面检查。
- 新建会话、重命名、删除、刷新恢复的浏览器回归。
- 专业工作台进入、返回、成果回流的浏览器回归。
- 任务补参、中断、恢复、确认、失败的浏览器回归。
- 无白屏、无乱码、无页面遮挡、无无意义嵌套滚动条。

## 11. 交付边界

- 本文是原型改造的产品与交互基线，后续实现任务应按 V1、V2 分阶段拆分，不一次性完成全部内容。
- 首轮开发仅执行 V1；V2 路由和数据结构可预留，但不提前展示未完成入口。
- 实施过程中不得为了技术方便改变版本边界或将工作台能力重新塞回对话卡片。
- 如开发评估需要裁剪 V1，优先保留统一入口、会话管理和成果关联，再裁剪新增智能体或非核心展示。
- 本轮未修改 App、后端需求、长期 Harness、部署或 Git 配置。
