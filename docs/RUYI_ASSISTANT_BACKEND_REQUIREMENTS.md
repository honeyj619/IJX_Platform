# 如意助手与如意空间后端需求文档

> 文档状态：产品需求稿  
> 适用范围：如意助手、如意空间、PC 消息入口及未来 App 接入  
> 当前原型说明：现阶段项目仅实现前端原型，本文件描述未来真实系统需要建设的后端能力，不要求在当前前端原型中实现。

## 1. 文档目的

当前产品原型已经展示如意助手在待办查询、知识检索、日程预约、项目立项、运营数据、公文、PPT、工作汇报等场景中的交互方式。为了避免前端原型承担真实服务端职责，需要将以下两部分明确分离：

- 前端原型负责展示入口、对话、任务状态、确认流程、结果和异常状态。
- 后端系统负责会话持久化、意图识别、Agent 调度、工作流执行、MCP 调用、权限校验、审计和跨端同步。

本文作为后端产品需求基线，后续可用于服务端架构设计、接口设计和研发拆分。

## 2. 产品角色与系统边界

### 2.1 如意助手

如意助手是企业级统一智能协同入口，负责：

- 接收来自 PC 消息、如意空间和未来 App 的自然语言请求。
- 识别用户意图和所需业务能力。
- 补充任务执行所需参数。
- 调度专业 Agent、Skill、工作流和 MCP 工具。
- 对高风险或写操作发起用户确认。
- 汇总执行结果并回传原入口。

### 2.2 如意空间

如意空间是 PC 端复杂任务工作台，负责承载：

- 会话历史与上下文。
- 长任务的步骤、进度和异常状态。
- 专业 Agent 或 Agent 团队的执行过程。
- 公文、PPT、周报、会议纪要等任务产物。
- 人工确认、修改、重试和继续执行。

### 2.3 专业 Agent、Skill 与 MCP

- 专业 Agent：面向知识、IT 服务、公文、汇报等领域承担分析和任务执行。
- Skill：可复用的专业能力或标准操作流程，例如公文生成、考勤查询、项目汇报生成。
- MCP/Connector：访问知识库、流程、日历、会议、通讯录和业务系统的底层工具。
- 工作流：编排参数收集、确认、工具调用、结果校验与回执的完整过程。

### 2.4 当前前端原型不承担的职责

- 不在浏览器端保存真实业务凭据、MCP Token 或系统密钥。
- 不在浏览器端直接调用企业生产系统。
- 不在浏览器端执行真实 Agent 编排或模型推理。
- 不在浏览器端判断最终数据权限。
- 不以 `setTimeout`、固定回复或正则匹配替代正式后端能力。
- 不要求当前 App 开发同步改造；App 后续通过统一接口接入。

## 3. 总体业务流程

标准任务链路如下：

1. 用户从 PC 消息、如意空间或 App 发起请求。
2. 后端创建或恢复会话线程。
3. 如意助手识别意图并匹配能力。
4. 系统提取执行参数，并对缺失参数发起追问。
5. 系统完成身份、权限、数据范围和工具可用性校验。
6. 查询类任务直接执行；写操作或敏感操作先请求用户确认。
7. 后端创建任务运行实例，按步骤调度 Agent、工作流和 MCP。
8. 执行过程持续产生状态事件，供前端展示进度。
9. 任务完成后保存结果、引用来源和产物。
10. 结果回传原入口，并支持在其他端打开同一会话或任务。

## 4. 功能需求

### 4.1 统一用户与身份

#### 4.1.1 统一用户标识

- PC、App 和企业 IM 中的同一员工必须映射到统一企业用户 ID。
- 支持员工、部门、岗位、角色、用户组及汇报关系信息。
- 用户离职、调岗或权限变化后，系统应及时更新可访问范围。

#### 4.1.2 渠道身份绑定

- 记录用户在 PC、App、企业 IM 等渠道中的身份映射。
- 所有渠道请求必须解析为统一用户身份后才能进入 Agent Runtime。
- 身份无法确认时不得执行企业数据查询或写操作。

### 4.2 统一会话与消息

#### 4.2.1 会话线程

- 支持创建、继续、重命名、归档和恢复会话。
- 每个会话记录所属用户、来源渠道、当前 Agent、上下文摘要、关联任务和最近活动时间。
- 不同渠道可以打开同一会话，但应保留消息来源渠道。
- 支持从 IM 会话跳转如意空间，并继续原有上下文。

#### 4.2.2 消息模型

消息至少支持：

- 用户文本、助手文本和系统消息。
- 图片、文件、语音及其他附件。
- 引用来源和知识文档链接。
- 参数确认、审批请求和任务状态。
- 业务结果、错误信息和任务产物。
- 专业 Agent 或团队成员消息。

#### 4.2.3 消息同步

- 新消息、任务进度和结果通过 WebSocket、SSE 或等价机制实时推送。
- 用户重新打开页面后应通过接口回读完整会话状态。
- 多端同时在线时需避免重复消息和状态覆盖。

### 4.3 能力识别与参数收集

#### 4.3.1 能力注册

每项能力应维护统一能力定义，至少包含：

- 能力编码和名称。
- 所属业务域和专业 Agent。
- 用户示例及触发条件。
- 输入参数 Schema。
- 必填参数和缺参追问规则。
- 执行前确认规则。
- 数据校验和权限要求。
- 工作流及 MCP Tool 映射。
- 成功结果、异常结果和留痕要求。

#### 4.3.2 意图识别

- 根据用户输入、当前会话和历史上下文识别最合适的能力。
- 出现多个候选意图时，向用户展示候选项，不得擅自执行高风险操作。
- 无匹配能力时提供普通问答或引导用户补充需求。

#### 4.3.3 Slot 参数收集

- 从自然语言、附件、用户资料和会话上下文中提取参数。
- 缺少必填参数时按业务顺序追问。
- 用户修改参数后必须覆盖旧值并记录变更。
- 进入工作台时需携带已确认参数，避免重复填写。

### 4.4 任务运行与步骤管理

#### 4.4.1 任务状态

任务至少包含以下状态：

- `draft`：参数收集中。
- `waiting_confirmation`：等待用户确认。
- `queued`：等待执行。
- `running`：执行中。
- `waiting_input`：等待用户补充信息。
- `waiting_approval`：等待权限或操作审批。
- `paused`：已暂停。
- `completed`：已完成。
- `failed`：执行失败。
- `cancelled`：已取消。

#### 4.4.2 任务步骤

- 复杂任务必须拆分为可观察步骤。
- 每一步记录执行 Agent、工具、开始时间、结束时间、输入摘要、状态和结果摘要。
- 前端只展示经过脱敏和产品化处理的步骤信息，不直接暴露模型思维链、密钥或内部提示词。
- 失败步骤支持重试；满足条件时可以从失败处继续，不必重新执行全部步骤。

#### 4.4.3 后台执行

- 用户离开页面后，长任务仍可继续执行。
- 执行完成、失败或需要人工处理时，通过原渠道通知用户。
- 支持用户主动取消尚未完成的任务。

### 4.5 Agent 与 Agent 团队

#### 4.5.1 专业 Agent

- 每个专业 Agent 配置职责、系统提示、可用 Skill、知识库、MCP、模型和数据权限。
- Agent 之间的工作区、记忆和工具权限应隔离。
- 如意助手作为协调者，可根据任务将子任务委派给专业 Agent。

#### 4.5.2 Agent 团队

- 复杂任务可由一个协调 Agent 和多个成员 Agent 协同完成。
- 协调 Agent 负责任务拆解、派工、结果汇总和完成判定。
- 成员 Agent 的阶段性结果需要回到同一任务时间线。
- 有在途任务时不得随意移除相关成员或删除 Agent。
- 团队执行失败时需明确失败成员、失败步骤及可恢复方式。

### 4.6 Skill、工作流与 MCP

#### 4.6.1 Skill 管理

- 支持 Skill 创建、版本、启用、停用、灰度范围和依赖检查。
- 一个 Skill 可被多个 Agent 使用，但需分别配置权限。
- Skill 变更后不得影响正在执行的历史任务版本。

#### 4.6.2 工作流编排

- 支持顺序步骤、条件分支、并行步骤、人工确认和失败补偿。
- 工作流版本发布后，新任务使用新版本，历史任务保留原版本。
- 工作流应能够调用内部服务、MCP 和专业 Agent。

#### 4.6.3 MCP/Connector 管理

- 支持知识库、流程、日历、会议、通讯录、门户消息和业务系统等连接器。
- 凭据必须在服务端加密保存，不下发浏览器。
- 每个 Agent 仅能调用授权的工具和操作。
- 工具调用需设置超时、重试、并发和熔断策略。
- 返回结果需进行结构校验、脱敏和错误标准化。

### 4.7 人工确认与审批

#### 4.7.1 操作风险分级

- 只读查询：在权限范围内可直接执行。
- 创建类操作：创建日程、创建会议、提交反馈、生成业务记录前需要确认关键参数。
- 修改类操作：修改日程、业务数据或已有文件前必须确认影响范围。
- 审批、发送、删除及外部发布：必须显式确认，必要时增加二次审批。

#### 4.7.2 确认请求

- 确认请求需包含操作名称、关键参数、目标对象、影响范围、有效期和风险说明。
- 用户可以批准、拒绝或要求修改参数。
- 确认过期后不得继续执行。
- 审批完成后任务从原步骤恢复。

### 4.8 知识库与引用

- 支持按 Agent 配置一个或多个知识库。
- 支持部门、用户组和文档级访问控制。
- 回答引用企业知识时应返回文档标题、来源、版本、更新时间和可访问链接。
- 用户无权访问的文档不得进入检索结果或模型上下文。
- 文档更新后支持增量索引和失效处理。
- 需要区分企业知识、用户上传材料和互联网公开信息。

### 4.9 文件、工作区与产物

- 每个任务可关联输入附件、中间文件和最终产物。
- 支持公文、PPT、周报、会议纪要、表格和导出文件等产物类型。
- 产物需记录创建任务、创建 Agent、版本、所有者、权限和有效期。
- 同一产物的修改应形成版本，不直接覆盖历史结果。
- 支持从消息或任务打开产物，并在权限允许时下载或继续编辑。
- 文件上传需进行类型、大小、病毒和敏感信息检查。

### 4.10 记忆与上下文

#### 4.10.1 记忆分层

- 会话上下文：仅服务当前线程。
- 任务上下文：保存任务参数、步骤和产物关系。
- 用户偏好：保存经过用户同意的稳定偏好。
- 企业知识：来自受控知识库，不作为个人记忆保存。

#### 4.10.2 记忆安全

- 不自动沉淀审批内容、人员敏感数据、薪酬、考勤明细等敏感信息。
- 用户可查看、纠正和删除个人记忆。
- 管理员可配置允许沉淀的记忆类别和保留期限。

### 4.11 定时任务与主动通知

- 支持一次性、按日、按周、按月及自定义 Cron 任务。
- 重复任务必须设置结束日期或结束条件。
- 定时任务可执行固定通知，也可先运行 Agent 再发送结果。
- 支持周报提醒、红黄灯项目汇总、待办提醒和会议前提醒等场景。
- 通知需记录目标渠道、接收人、发送状态和失败原因。
- 相同任务不得因重复调度而多次发送。

### 4.12 多端与渠道适配

- Web、PC 消息、App 和企业 IM 共用统一会话与任务服务。
- 各渠道可使用不同展示组件，但不得复制业务执行逻辑。
- 富卡片不可用时，后端需返回文字摘要和业务链接作为降级方案。
- App 后续接入时，应支持会话列表、任务状态、确认操作、结果通知和深链跳转。
- 渠道断线重连后应恢复未读消息和最新任务状态。

### 4.13 管理后台

管理后台需提供以下配置能力：

- Agent 列表、创建、编辑、启停、发布范围和版本。
- Agent 团队、协调者和成员配置。
- Skill 列表、版本、依赖、启停和灰度范围。
- 工作流定义、版本、发布和回滚。
- MCP/Connector 目录、授权、健康状态和可用工具。
- 知识库、数据范围和索引状态。
- 定时任务和通知渠道。
- 操作风险等级、确认策略和审批策略。
- 会话、任务、工具调用、异常和用户反馈查询。
- 模型用量、工具调用量、任务成功率和平均耗时统计。

### 4.14 审计、权限与安全

- 所有请求必须执行身份认证和服务端权限校验。
- 权限至少覆盖功能、Agent、Skill、工具、部门、人员和数据对象范围。
- 记录用户输入摘要、能力选择、参数确认、工具调用、结果状态和操作人。
- 审计记录需防篡改，并支持按用户、任务、工具、时间和业务对象查询。
- 日志和模型上下文中的身份证、手机号、邮箱、薪酬等敏感数据需脱敏。
- 密钥、Token、Cookie 和连接器凭据不得出现在前端响应或普通日志中。
- 支持工具调用频率限制、异常检测和紧急停用。

## 5. 首批业务能力范围

### 5.1 查询型能力

- 待办与待审批查询。
- 考勤统计与制度查询。
- 企业知识检索。
- 运营数据查询。
- 工作汇报和项目状态统计。

查询结果需返回数据来源、查询时间、适用范围和业务详情链接。

### 5.2 事务型能力

- 创建或修改日程。
- 发起或预约会议。
- 项目立项申请。
- 产品反馈和 IT 工单提交。
- 工作汇报提交与通知。

事务型能力必须执行参数补齐、权限校验、用户确认和结果回执。

### 5.3 内容生产能力

- 公文创作和校验。
- PPT 生成与调整。
- 项目周报和工作汇报生成。
- 会议纪要生成。

内容生产能力需支持长任务、工作台接续、版本管理和最终产物回传。

## 7. 接口需求原则

后续接口设计应至少覆盖：

- 会话创建、列表、详情、归档和继续对话。
- 消息发送、流式响应、历史回读和多端同步。
- 任务创建、详情、步骤、取消、重试和继续。
- 确认请求的批准、拒绝和参数修改。
- Agent、团队、能力和 Skill 查询。
- 文件上传、产物列表、预览、下载和版本查询。
- 定时任务创建、修改、停用和执行记录。
- 管理后台配置、发布、审计和统计。

接口必须满足：

- 使用稳定 ID，不以页面展示名称作为关联主键。
- 写操作支持幂等键，避免重复提交。
- 列表接口支持分页、筛选和排序。
- 错误返回统一错误码、用户提示和可恢复建议。
- 流式事件具有事件序号，支持断线续传或状态回读。
- 所有接口执行服务端权限校验。

## 8. 非功能需求

### 8.1 可用性

- 核心会话与查询服务应具备明确的超时和降级策略。
- 单个 MCP 或专业 Agent 故障不得导致整个会话服务不可用。
- 后台任务需支持重试和失败通知。

### 8.2 性能

- 普通消息提交后应尽快返回已接收状态。
- 长任务应先返回任务 ID，再异步推送进度。
- 会话历史和任务列表需支持分页，禁止一次返回全部数据。

### 8.3 可观测性

- 支持按会话、任务、Agent、能力和工具追踪请求链路。
- 统计成功率、失败率、平均耗时、Token 用量和工具调用量。
- 告警需区分模型异常、工具异常、权限异常和业务校验异常。

### 8.4 数据保留

- 会话、任务、附件、产物和审计记录分别配置保留期限。
- 到期清理需遵循企业档案、审计和安全要求。
- 用户删除会话不等同于删除审计记录，需按制度分别处理。

## 9. 验收标准

### 9.1 会话闭环

- 用户在 PC 消息中发起任务，可在如意空间打开同一会话。
- 进入如意空间后保留原问题、已确认参数和执行进度。
- 完成结果可回传 PC 消息；未来 App 接入后可读取相同结果。

### 9.2 任务闭环

- 复杂请求能够形成任务和步骤。
- 用户离开页面后任务仍可继续。
- 任务支持等待补充、等待确认、失败、重试、取消和完成状态。
- 任务产物可追溯到原会话和执行版本。

### 9.3 权限闭环

- 未授权用户不能通过自然语言绕过业务系统权限。
- 写操作必须按风险等级完成确认或审批。
- 管理员可以查询完整的任务、工具调用和确认记录。

### 9.4 场景闭环

- 待办、考勤、知识、运营数据等查询能返回来源与详情入口。
- 日程、会议、立项、反馈和汇报提交完成参数确认和结果回执。
- 公文、PPT、周报和会议纪要能进入工作台继续编辑并生成产物。
- 定时提醒能够按规则执行并记录发送结果。

## 10. 分期建议

### 第一阶段：统一基础服务

- 用户与渠道身份。
- 会话、消息和跨端同步。
- 能力注册、Slot 收集和统一错误模型。
- 任务、步骤、确认和基础审计。

### 第二阶段：核心业务闭环

- 待办、知识、考勤、运营数据查询。
- 日程、会议、立项和反馈工作流。
- 公文、PPT、周报等长任务与产物管理。

### 第三阶段：Agent 平台化

- 专业 Agent、Agent 团队和 Skill 管理。
- Connector/MCP 管理与工具权限。
- 记忆、知识库、定时任务和主动通知。

### 第四阶段：多端与运营治理

- App 接入统一协议。
- 管理后台完整配置。
- 用量、质量、安全、审计和运营分析。
