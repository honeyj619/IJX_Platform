# IJX Platform 客户端设计规范

版本：1.3
适用范围：`/pc_client` 下的客户端页面
设计基线：消息、日历设计稿与品牌配色规范

## 1. 设计原则

- 整体气质为轻量、克制、清晰的企业协同工具，不使用营销页式的大标题、装饰卡片和强烈阴影。
- 页面由“底面背景”和“白色工作面”构成。底面背景必须在工作面四周和分栏间隙可见，不能被整页白底完全覆盖。
- 页面结构优先表达工作关系：导航、列表、内容区各自独立，避免卡片套卡片。
- 同类页面使用相同分栏、圆角、边框和滚动规则，不在页面内重新定义另一套视觉体系。

## 3. 页面骨架

### 3.1 底面与工作面

- 客户端视口四周保留 `8px` 底面背景。
- 同级工作面之间保持 `8px` 间距。
- 一级工作面圆角统一为 `16px`，边框为白色半透明或 `#E4E7ED` 弱边框。
- 工作面阴影只用于轻微区分层级，推荐 `0 1px 3px rgba(48,49,51,.06)`。
- 一级工作面必须填满可用高度；内部滚动，浏览器页面本身不产生多重纵向滚动条。

### 3.2 全局导航

- 桌面展开宽度为 `168px`，折叠宽度为 `64px`。
- 导航直接展示底面背景，不增加整栏底色、模糊层或独立卡片背景；工作区以白色工作面浮在其上。
- 展开态主导航项高度统一为 `42px`、圆角 `8px`，导航文字字重统一为 `600`；折叠态保留不小于 `44px` 的图标点击区域。
- 导航用户头像使用 `12px` 圆角且不显示边框，用户名使用标题黑。
- 导航选中项使用白色背景、标题黑和品牌色图标；未选中项使用中级黑。
- 主导航图标统一使用 `lucide-react`，尺寸 `18-20px`，文字 `14px`。

### 3.3 消息页面：三块布局

消息页面由三个视觉工作块组成：

1. 全局导航，宽 `168px`。
2. 会话列表，建议宽 `252-280px`，列表顶部不单独设置搜索或新建按钮。
3. 会话内容，自适应剩余宽度，包含固定会话头、消息流和固定输入区。

三块之间均露出 `8px` 底面背景。会话列表和消息流分别独立滚动，头部和输入区不得随内容滚动。新增链接等全局能力继续保留在全局导航原有位置，不在消息列表重复设置入口。

### 3.4 日历及常规页面：两块布局

日历、工作门户、业务系统、如意空间等常规页面按两块布局处理：

1. 全局导航。
2. 单一主工作面。

主工作面内部可以继续设置功能侧栏与内容区，但它们属于同一个工作面，使用分割线衔接，不再露出底面间隙。日历内部左栏承载搜索、小月历和日历列表，右侧承载日/周/月视图。

### 3.5 工作台页面

- 公文、PPT、参谋师等工作台仍作为一个主工作面呈现。
- 工作台内部允许缩略图栏、画布、属性栏等多栏结构，但外层必须遵守全局两块布局和独立滚动规则。
- 固定操作栏和属性栏不可覆盖画布内容；窄屏下优先收缩内部侧栏。

## 4. 文字与间距

- 字体顺序：`PingFang SC`、`Microsoft YaHei`、`Noto Sans CJK SC`、系统无衬线字体。
- 页面标题 `20-24px / 600`；模块标题 `16-18px / 600`；正文 `14px / 400`；辅助文字 `12px / 400`。
- 字间距保持 `0`，不使用负字距。
- 基础间距单位为 `4px`，常用间距为 `8 / 12 / 16 / 24px`。
- 紧凑工具栏高度建议 `48-56px`；列表项最小可点击高度 `48px`。

## 5. 组件规则

- 命令按钮使用图标或“图标 + 文本”；熟悉的操作优先使用图标并提供 `title`。
- 主按钮使用品牌主色；次按钮使用白色或浅灰背景，不使用大面积渐变。
- 输入框圆角 `8px`，默认背景可用 `#F5F7FA`，聚焦时使用品牌色描边。
- 表单输入区不放装饰性图标（联系人、搜索等前置图标仅用于独立的搜索入口，表单字段内直接呈现标签与输入）；复合输入（标签 + 输入行）与同行按钮按 `36px` 等高对齐，多行时按钮顶对齐。
- 卡片仅用于可重复的信息实体、弹窗和独立工具，不把整个页面章节包装成悬浮卡片。
- 弹窗圆角不超过 `16px`，高风险操作必须二次确认。

### 5.1 交互载体与独立子窗口

- Modal、Popover、Drawer、主窗口新页面和独立子窗口的选择与行为，以 `docs/CLIENT_INTERACTION_SURFACES.md` 为权威规范；不允许只因现有代码已经使用弹框就继续沿用。
- 创建日程、预约会议及其编辑流程的目标外层载体为独立任务窗口，不显示全局导航；Web 原型在同一应用视口内绘制窗口，不拉起浏览器新页。通讯录、会议室、自定义重复和放弃修改确认属于窗口内部 Modal。
- 当前 PC 原型按 Windows 环境表达：标题与应用标识在左、窗口控制在右，不使用 macOS 交通灯。具体操作系统皮肤不是业务组件强规范，真实客户端以原生壳为准。
- 独立任务窗口沿用本文件的颜色、字体、工作面、圆角与间距令牌，不另造品牌体系；客户端氛围背景图只出现在窗口外侧舞台，不能进入业务工作面或模拟控件。

### 5.2 业务消息卡片

应用推送与如意助手查询结果共用同一套业务消息卡片，不按入口复制两套组件。卡片采用飞书消息卡片的成熟信息层级，但原型只保留展示与前端跳转，不表达接口、回调、卡片更新或服务端参数。

- 必选字段：卡片 ID、业务分类、来源、标题、跳转动作。
- 可选字段：副标题、摘要、状态、关键指标、详情字段、重复事项、标签、时间。
- 标题区按“来源 / 分类 / 标题 / 状态”组织；状态使用语义色，不单独依赖图标表达。
- 指标用于考勤、经营、项目进度等数值摘要；详情字段用于申请人、周期、地点等键值信息；重复事项用于待办、流程、知识和日程列表。
- 卡片正文、事项行和底部动作均可配置前端路由。主操作最多一个，次操作和文字链接按业务需要补充。
- 同一业务对象在应用推送和如意助手回复中必须复用同一数据结构与组件；入口差异只体现在上下文说明，不改变卡片字段语义。

## 6. 状态与反馈

- 选中态必须同时体现背景和文字/图标变化，不能只依赖颜色差异很小的边框。
- 加载、空状态、失败和完成状态都必须有明确文案与下一步操作。
- 删除、覆盖、重新生成等不可逆操作必须确认。
- 数据发生变化后提供可见反馈；禁止无提示静默完成。

## 7. 响应式与滚动

- Web Client 固定最小宽度 `1024px`：低于该宽度时不重排、不缩字号、不切换移动模式，由最外层 `web-client-viewport` 横向滚动。
- 全局导航始终处于正常文档流，不切换为覆盖式抽屉，不出现遮罩和移动端顶栏。
- 拖动条始终可用，不随视口宽度隐藏。
- 窄屏优先收缩侧栏、折叠工具，不通过缩小字号解决空间问题。
- 固定格式区域使用明确的宽度、网格或 `minmax`，避免内容变化引发布局跳动。
- 消息列表、会话内容、页面属性栏等区域独立滚动；默认隐藏滚动条，悬浮时显示。
- 禁止同一页面同时出现浏览器级和多个无意义的嵌套滚动条；横向滚动唯一来源是 `web-client-viewport`。
- `/admin`、`/download` 等独立页面不套用客户端视口，保留各自的响应式行为。

## 8. 实施检查清单

- 底面背景是否在页面四周和分栏之间可见。
- 消息页是否为导航、会话列表、会话内容三块结构。
- 其他客户端页面是否为导航和主工作面两块结构。
- 主工作面是否统一使用 `16px` 圆角和 `8px` 外间距。
- 配色是否使用语义变量与官方品牌色。
- 页面在 1440、1280、1024 宽度下是否无重叠、无横向溢出。
- 800、600 固定画布下 Web Client 是否保持 1024 布局，由最外层横向滚动，无重排、无缩字号、无移动模式切换。
- 头部、内容、底部操作区的滚动关系是否正确。
- 深色模式是否保持文字对比度和边界可辨识度。
- 完成后是否通过类型检查、生产构建和关键路由浏览器回归。

## 业务卡片与消息功能条（V3.5 如意助手）

### 卡片判定（满足任一即用卡片）
- 返回可打开或可继续操作的业务对象
- 返回多个字段、指标、状态或列表项
- 用户需从结果直接进入业务页面执行下一步
- 需要展示来源系统、时间、状态和主操作
- 任务确认/恢复/成果/权限/错误等明确状态对象

保持文本不强行卡片化：普通问答、简短翻译、能力切换提示、简短补参问题。

### 能力 → 卡片映射
| 能力 | 形式 |
| --- | --- |
| 待办/审批、考勤、日程、项目、知识、运营、IT | `BusinessMessageCard`（approval/attendance/schedule/project/knowledge/notice 卡） |
| 会议创建成功 | 会议结果卡（meeting category，`buildMeetingCreatedCard` 按任务 slots 动态生成，内容与确认摘要同源） |
| 会议参数确认/任务恢复/多任务选择 | `RuyiConfirmationMessage` / `RuyiTaskResumeMessage` / `RuyiMultiTaskResolver` |
| 公文/PPT/周报（参谋）插件提交 | 不挂卡片——提交直达对应工作台（`directWorkbench`：写轻量需求记录 + 预写 launchContext + 页面导航） |
| 对话中的参谋/汇报需求（"帮我写周报"） | 参谋需求卡（workbench category，`buildWorkbenchEntryCard` 预填类型/周期/来源，CTA 直达参谋师工作台） |
| 公文/PPT/周报最终成果 | `RuyiResultCard` |
| 翻译/普通问答 | 文本 + 通用功能条 |

### 通用功能条（每条完成态助手回复固定显示）
- 复制 / 有用 / 没用 / 重新生成由 `RuyiMessageToolbar` 渲染器统一生成，不依赖消息 actions 数据；loading 与系统消息不显示。
- 卡片 footer 是业务动作；消息功能条是复制/反馈/重新生成——两者不能合并、不重复。
- 卡片已有 CTA 时消息层不再生成同义业务按钮。
- 卡片只服务对话流呈现；插件面板提交不产生卡片（直达工作台），两者不得混用。

### 布局
- IM compact 卡片四项指标用 2×2；卡片不得被固定高度裁切。
- 卡片后的功能条与卡片 footer 保持 8~12px 间距。
- 历史会话首次打开从顶部展示；仅当用户接近底部时新消息才自动滚底。

## 消息对话滚动规范（全局强制，2026-11-19）

适用于**所有消息对话场景**：PC 消息页（普通会话/应用推送卡片会话/如意助手会话）、如意空间会话页。新增任何消息对话视图必须遵守，不得各自实现另一套滚动策略。

### 规则

1. **打开即置底**：进入或切换任何对话，滚动区直接定位到底部（最新消息），与主流 IM 产品一致。不做"首次打开从顶部开始"。
2. **发新消息保持最底**：用户发送消息或收到新回复时，若用户在底部附近（距底 < 120px），自动平滑滚动到底部跟新。
3. **上翻不打扰**：用户主动上翻查看历史消息时，新消息到达不强制拉底；一旦用户回到接近底部，恢复自动跟随。
4. **实现基线**：切换会话 `scrollTop = scrollHeight`；追加消息按 nearBottom 判断后 `scrollIntoView({ behavior: "smooth" })`。参考 `RuyiConversationView.tsx` / `Home.tsx` 的滚动 effect。
