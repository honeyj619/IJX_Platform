# IJX Platform UI 设计规范

> 状态：项目级强制规范  
> 版本：1.1  
> 更新日期：2026-10-09  
> 适用范围：IJX Platform Web 客户端、工作门户、如意空间、业务工作台及管理类页面  
> 设计依据：消息页设计稿、日历页设计稿、《规范-01-配色》

## 1. 使用方式与优先级

本规范是后续页面设计、开发、评审和验收的默认基线。新增页面和修改现有页面时，必须先对照本规范，再沿用相邻页面已有组件。

规则优先级从高到低：

1. 用户明确确认的当前页面设计稿或交互要求。
2. 本规范中的颜色、布局、组件和状态规则。
3. 项目已有的同类页面与组件实现。
4. 开发者自行补充的表现形式。

如果新的已确认设计稿与本文冲突，应同步更新本文，避免只在单个页面形成例外。未经确认，不得自行改变品牌主色、基础明暗色或整体导航结构。

## 2. 设计原则

### 2.1 产品气质

- 定位为高频使用的企业协同工具，不采用营销页或展示型产品的视觉表达。
- 页面应克制、轻量、安静，以信息扫描、连续操作和多任务切换效率为优先。
- 品牌色只用于主要操作和关键选中状态，不大面积铺满内容区。
- 层级主要通过留白、分割线、背景明度和字重建立，避免依赖重阴影和大量卡片。
- 功能页面直接展示可用工作区，不增加大幅宣传式标题、装饰图形或无关说明。

### 2.2 信息层级

页面信息从外到内依次为：

1. 全局导航：切换消息、工作门户、日历、知识库、业务系统、如意空间等一级功能。
2. 业务侧栏：搜索、列表、日期导航、筛选或当前业务上下文。
3. 主工作区：当前对象详情、编辑器、日历网格、对话或业务内容。
4. 浮层：菜单、弹窗、抽屉和二次确认，仅在需要时覆盖主工作区。

同一层级不重复使用标题、边框和卡片进行多重强调。

## 3. 布局规范

### 3.1 参考画布

- 设计稿参考逻辑画布为 `1440 × 960`。
- 桌面端以可视区域铺满为主，应用根节点使用 `100vw × 100vh`。
- 页面外层不产生无意义的整体横向滚动；列表、表格、日历和内容画布可在自己的区域内滚动。

### 3.2 桌面三栏结构

| 区域 | 建议宽度 | 规则 |
| --- | ---: | --- |
| 全局导航 | `168px` | 固定宽度，包含用户信息、一级导航、已打开页面和底部操作 |
| 业务侧栏 | `250–260px` | 消息列表、日期导航、筛选等；无二级导航的页面可省略 |
| 主工作区 | `minmax(0, 1fr)` | 占用剩余空间，内容独立滚动，不被侧栏挤出视口 |

- 栏间使用 `8px` 左右的视觉间隔或明确分割线，不使用重阴影切割区域。
- 主工作区应为第一视觉重点，侧栏保持较低视觉噪声。
- 消息类页面采用“全局导航 + 会话列表 + 对话区”。
- 日历类页面采用“全局导航 + 日期/日历列表 + 日历网格”。
- 工作台类页面可采用“全局导航 + 主画布 + 固定属性面板”，但颜色、边框和控件规则保持一致。

### 3.3 顶部与底部区域

- 页面顶部栏建议高度 `56–64px`；页面级标签、标题和主要操作保持同一基线。
- 业务顶部栏吸顶，主内容在其下方独立滚动。
- 对话输入区、确认操作区等高频底部控件应固定在当前工作区底部，而非固定到整个浏览器窗口。
- 固定区域必须预留内容空间，不能覆盖列表最后一项或编辑器正文。

### 3.4 滚动规则

- 每个方向优先只保留一个主滚动容器。
- 全局导航、业务侧栏、主工作区可分别纵向滚动，但默认隐藏滚动条，悬停或操作时显示。
- 表格宽度不足时，仅表格容器横向滚动；页面本身不得横向滚动。
- 吸顶栏、底部操作栏和固定侧栏不随正文滚出视口。

## 4. 颜色规范

### 4.1 基础色令牌

以下颜色来自《规范-01-配色》，为项目唯一基础色源。

| 颜色定义 | Light | Dark | 使用场景 |
| --- | --- | --- | --- |
| 品牌主色 | `#B82971` | `#B82971` | 主按钮、标题强调、选中 Tab、文字链接、关键日期和主要选中状态 |
| 标题黑 | `#303133` | `#E5EAF3` | 页面标题、模块标题、重要正文、核心数值 |
| 中级黑 | `#606266` | `#CFD3DC` | 正文、说明文字、图标、次要操作 |
| 最弱色 | `#909399` | `#A3A6AD` | 占位文字、时间戳、禁用或弱提示文字 |
| 分割线 | `#E4E7ED` | `#414243` | 区域分隔、列表分割、输入框边界、日历网格 |
| 页面背景 / 色块容器 | `#F5F7FA` | `#262727` | 页面背景、输入底色、工具栏色块、弱化容器 |
| 选中项背景 | `#EBEDF0` | `#39393A` | 菜单、列表、Hover 和次级选中背景 |
| 二级页卡片背景 | `#FFFFFF` | `#141414` | 二级页面、主工作面、弹窗和需要独立承载内容的容器 |

### 4.2 CSS 变量建议

后续新增样式优先使用语义变量，不直接散落十六进制颜色或 `pink-*` 色阶。

```css
:root {
  --ui-brand-primary: #B82971;
  --ui-text-title: #303133;
  --ui-text-body: #606266;
  --ui-text-weak: #909399;
  --ui-border: #E4E7ED;
  --ui-surface-page: #F5F7FA;
  --ui-surface-selected: #EBEDF0;
  --ui-surface-card: #FFFFFF;
}

.dark {
  --ui-brand-primary: #B82971;
  --ui-text-title: #E5EAF3;
  --ui-text-body: #CFD3DC;
  --ui-text-weak: #A3A6AD;
  --ui-border: #414243;
  --ui-surface-page: #262727;
  --ui-surface-selected: #39393A;
  --ui-surface-card: #141414;
}
```

### 4.3 主色使用规则

主色用于：

- 页面唯一主要操作按钮。
- 当前 Tab 的文字、下划线或实底状态。
- 选中日期、复选框、单选框和关键状态点。
- 可点击的重点文字链接。
- 需要与普通信息明显区分的业务强调。

主色不得用于：

- 大面积正文背景。
- 多个同级按钮同时实底展示。
- 普通说明文字和无交互图标。
- 用作错误、警告、成功等语义状态的替代色。

设计稿未定义完整主色色阶。需要 Hover、Active 或浅色背景时，应优先通过透明度或 `color-mix()` 从 `#B82971` 派生，避免人工新增不一致的粉色：

```css
--ui-brand-hover: color-mix(in srgb, var(--ui-brand-primary) 88%, black);
--ui-brand-active: color-mix(in srgb, var(--ui-brand-primary) 78%, black);
--ui-brand-tint: color-mix(in srgb, var(--ui-brand-primary) 7%, var(--ui-surface-card));
```

### 4.4 语义状态色

当前配色稿未定义成功、警告、错误、信息色。开发时应遵循以下规则：

- 优先复用项目已有语义色，不因页面不同创建新色。
- 状态必须同时通过图标或文字表达，不能只依赖颜色。
- 未经补充设计稿确认，不把品牌主色当作错误色或警告色。
- 后续收到正式语义配色时，应在本文追加统一令牌。

## 5. 字体与排版

### 5.1 字体

设计稿要求使用系统默认字体。推荐字体栈：

```css
font-family: "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC",
  "Segoe UI", sans-serif;
```

- 不额外下载或嵌入展示型字体。
- 中文、英文和数字应保持系统 UI 字体的一致观感。
- 正文默认不使用斜体、描边或负字距。

### 5.2 字号层级

| 层级 | 字号 | 字重 | 使用场景 |
| --- | ---: | ---: | --- |
| 页面标题 | `20px` | `600–700` | 页面名称、核心对象名称 |
| 一级模块标题 | `16–18px` | `600` | 侧栏分组、内容区模块标题 |
| 正文 / 控件 | `14px` | `400–500` | 正文、列表、输入框、按钮 |
| 辅助文字 | `12px` | `400` | 时间、说明、计数、次要状态 |
| 紧凑标识 | `11px` | `500–600` | Badge、角标；仅在空间受限时使用 |

- 正文行高建议 `1.5–1.7`，标题行高建议 `1.3–1.5`。
- 同一区域最多使用三级文字层级，避免字号过多。
- 时间、辅助信息使用最弱色；不能通过继续缩小字号来弱化信息。

## 6. 间距、圆角、边框与阴影

### 6.1 间距

- 采用 `4px` 基础网格。
- 常用间距：`4 / 8 / 12 / 16 / 24 / 32px`。
- 控件内部水平留白通常为 `12–16px`。
- 模块间距通常为 `16–24px`，页面主区边距通常为 `20–24px`。
- 列表行应保持稳定高度，动态内容不得导致相邻控件跳动。

### 6.2 圆角

| 类型 | 圆角 |
| --- | ---: |
| 小型标签、头像、日期按钮 | `6px` 或圆形 |
| 输入框、按钮、列表选中项 | `8px` |
| 面板、弹窗、主工作面 | `12–16px` |

- 只有 Badge、头像、日期点等明确语义元素使用全圆角。
- 不把所有文字操作都做成胶囊按钮。
- 避免卡片套卡片；需要分组时优先使用标题、分割线和背景明度。

### 6.3 边框与阴影

- 基础边框为 `1px solid var(--ui-border)`。
- 列表项之间优先使用单边分割线，不给每一行单独加完整边框。
- 常规工作区尽量无阴影；弹窗、下拉菜单、悬浮工具可使用轻阴影。
- 禁止重阴影、彩色发光和装饰性浮空卡片。

## 7. 组件规范

### 7.1 全局导航

- 浅色模式使用项目资产 `/public/assets/navigation-background.png` 作为全局导航背景，左上对齐并覆盖导航区域；不得用代码渐变替代该正式背景图。
- 一级导航使用图标加文字，图标尺寸建议 `18–20px`。
- 当前项使用白色或选中背景承载，品牌色仅强调图标、文字或状态点。
- 默认图标使用中级黑；选中图标使用品牌主色，并可用导航辅助色 `#D49A73` 表达双层图形中的次要部分。
- 一级入口固定顺序为：消息、工作门户、日历、知识库、业务系统、如意空间。
- 未读数使用紧凑 Badge，放在条目右侧，不改变条目布局宽度。
- “打开的页面”显示页面名称，不显示原始 URL。
- 导航底部操作与顶部主导航分开，不与业务列表混排。

### 7.2 Tab 与分段控制

- 页面级 Tab 使用文字加底部品牌色指示线，避免全部做成卡片。
- 模式切换可使用紧凑分段控制，选中项背景为卡片色或品牌色。
- 同一组只允许一个选中项；切换时内容区域位置保持稳定。

### 7.3 按钮

- 主要按钮：品牌色实底、白字，每个操作区原则上只保留一个。
- 次要按钮：卡片背景、分割线边框、中级黑文字。
- 图标按钮：`36–40px` 稳定正方形，有 `title` 或 Tooltip。
- 常规文字按钮高度建议 `36–40px`，主流程按钮可为 `40–44px`。
- 禁用态使用最弱文字和页面背景，同时禁用点击和键盘操作。

### 7.4 输入、搜索和选择控件

- 输入框背景使用页面背景色或卡片色，边框使用分割线色。
- 搜索框左侧使用搜索图标，Placeholder 使用最弱色。
- 聚焦时显示品牌色边框和清晰 Focus Ring，不改变控件尺寸。
- 下拉、日期、筛选等控件高度保持一致；同一工具栏不得混用多种高度。
- 多行输入区固定最小高度，右下角可展示字数，但不能挤压正文。

### 7.5 列表与列表项

- 列表以分割线组织，头像、标题、摘要、时间保持固定列关系。
- 主标题一行，摘要通常一行省略；需要完整内容时进入详情。
- 选中行使用低浓度品牌色背景或选中项背景，不使用粗边框包围。
- Hover 只改变背景，不移动、缩放或改变列表高度。
- 空状态显示简短原因和唯一下一步操作，不放大幅插画占据工作区。

### 7.6 对话界面

- 对方消息左对齐，使用页面背景色气泡；本人消息右对齐，使用低浓度品牌色气泡。
- 气泡宽度随内容增长，但不超过对话区约 `70%`。
- 连续消息可省略重复头像；跨时间段在中间展示弱化时间。
- 输入区固定在对话区底部，与消息列表之间使用分割线。
- 消息正文优先保证可读性，不使用大圆角、重阴影或高饱和底色。

### 7.7 日历界面

- 顶部按“页面 Tab / 新建操作 / 当前年月 / 视图切换”分区排列。
- 月视图使用等宽七列，网格线统一使用分割线色。
- 今天使用品牌色实心圆；侧栏选中日期可使用品牌色描边圆。
- 非本月日期使用最弱色；节日、农历等辅助信息不得抢占日期数字层级。
- 日程以品牌色状态点加时间、标题展示，不使用独立浮动卡片破坏网格。

### 7.8 弹窗、抽屉和菜单

- 弹窗用于确认、选择和聚焦编辑；抽屉用于保留主页面上下文的详情或配置。
- 标题、内容、操作区必须清晰分层，底部按钮右对齐或遵循现有工作台规则。
- 删除、清空、覆盖、重新生成等不可逆操作必须二次确认。
- 遮罩不能完全遮蔽上下文，弹窗内部内容过长时仅正文区滚动。

## 8. 交互与状态

每个可交互组件至少考虑以下状态：

- Default：默认可操作状态。
- Hover：使用选中项背景或低浓度品牌色背景。
- Focus：键盘可见的品牌色 Focus Ring。
- Active / Selected：品牌色或选中项背景，且有文字或图标辅助。
- Disabled：最弱色、不可点击、不可聚焦。
- Loading：保持原尺寸，显示加载图标或骨架，不引发布局跳动。
- Empty：说明原因并提供唯一主要操作。
- Error：在对应控件附近给出原因和恢复方式。

异步操作必须有可见反馈。保存、提交、上传、生成等操作成功或失败后，应使用 Toast、状态标签或结果页明确反馈。

## 9. 图标、头像与图片

- 项目图标统一优先使用 `lucide-react`；同一页面不混用多套描边风格。
- 常用尺寸为 `16 / 18 / 20 / 24px`，线宽保持一致。
- 不使用 Emoji 代替功能图标，不手绘已有标准图标。
- 头像在列表中建议 `36–40px`，在全局用户区可为 `28–32px`。
- 图片使用固定比例和 `object-fit: cover`，加载失败时显示姓名首字或标准占位。

## 10. 响应式规则

现有设计稿为桌面端，以下为开发实施时的响应式扩展规则：

### `≥ 1280px`

- 完整展示全局导航、业务侧栏和主工作区。
- 保持桌面高信息密度和固定栏宽。

### `768–1279px`

- 优先收窄或折叠业务侧栏；全局导航可切换为图标栏或抽屉。
- 主工作区保持主要操作和内容可见。
- 宽表格在自身容器内横向滚动。

### `< 768px`

- 一次只展示一个主层级，导航与详情使用抽屉或独立页面。
- 顶部操作允许换行，但主要按钮不得被挤出视口。
- 弹窗宽度适配视口，表单改为单列。
- 固定底部操作区需考虑安全区，并确保不遮挡内容。

## 11. 暗色模式

- 暗色模式必须使用第 4 节给出的对应色值，不直接反相浅色页面。
- 图片、头像和业务截图不反相。
- 主色 `#B82971` 保持不变，但需检查其与暗色卡片背景的文字对比度。
- 暗色页面不得继续使用浅色阴影；层级优先依靠 `#262727`、`#39393A`、`#141414` 和 `#414243` 区分。
- 新组件必须同时检查 Light 与 Dark，不允许只写 `.dark .bg-white` 式的零散覆盖作为最终方案。

## 12. 可访问性

- 正文和背景对比度应达到 WCAG AA；小号文本不得仅靠低对比度弱化。
- 键盘操作必须能到达按钮、链接、Tab、列表选择项和表单控件。
- Focus 状态不可被移除，且不能只使用颜色变化。
- 图标按钮必须提供 `aria-label`、`title` 或 Tooltip。
- 点击目标建议不小于 `36 × 36px`；移动端不小于 `44 × 44px`。
- 状态色必须配合文本或图标，不用“仅红色/仅绿色”表达结果。
- 文本缩放至 `200%` 时不得遮挡或截断主要操作。

## 13. 项目落地规则

### 13.1 Tailwind 与语义令牌

- 新增页面优先使用语义化主题变量，不直接新增大量 `pink-*`、`gray-*` 硬编码。
- 现有页面允许渐进迁移；修改某个组件时，应优先把该组件涉及的颜色映射到本规范令牌。
- `#B82971` 是品牌主色，不以当前 Tailwind `pink-600` 或 `pink-700` 近似替代。
- 颜色令牌应集中定义，禁止在多个页面重复维护相同十六进制值。

### 13.2 组件复用

- 开发前先搜索 `src/components/` 和相邻页面，复用已有按钮、选择器、弹窗、空状态和工作台结构。
- 跨两个以上页面使用的交互组件应提取到 `src/components/`。
- 页面内私有组件可保留在页面文件底部，但必须遵循本规范的令牌与状态规则。

### 13.3 禁止项

- 禁止大面积高饱和品牌色背景。
- 禁止无功能意义的渐变球、光斑、装饰插画和重阴影。
- 禁止页面区块全部卡片化或卡片嵌套卡片。
- 禁止用 URL 代替页面名称、用文字按钮代替已有标准图标。
- 禁止控件在 Hover、Loading、文字变化时改变布局尺寸。
- 禁止在同一页面混用不同圆角、图标风格和按钮高度。
- 禁止为单个页面私自新增一套灰色、主色或暗色模式。
