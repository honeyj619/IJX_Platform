# IJX Platform 客户端交互载体规范

版本：1.1
适用范围：`/pc_client` 下的 PC 客户端主窗口、独立任务子窗口及其内部浮层
参考基线：现有 React 原型、客户端创建日程参考图、`docs/UI_DESIGN_GUIDELINES.md`

## 1. 目的与边界

本规范用于在实现功能前确定“操作承载在哪里”，统一弹框、浮层、侧边抽屉、主窗口新页面和独立子窗口的选择与行为，避免每个业务模块自行决定交互载体。

- 本规范只约束 PC 客户端；管理后台继续遵循 `docs/ADMIN_UI_GUIDELINES.md`，Vue App 继续遵循 `src/prototype/harness/`。
- 交互载体由任务复杂度、上下文依赖和并行工作需要决定，不按开发便利或组件现状决定。
- 业务流程、字段和状态仍以需求模式与对应业务规范为准；本文件只统一承载形式、窗口关系和通用交互。
- 参考图只能用于提炼信息结构、任务分区和交互关系，不得照抄其操作系统皮肤。当前原型统一按 Windows 桌面环境表达；若未来增加 macOS 演示，必须切换完整平台壳，不得在同一窗口混用两套控件。
- Harness 不把 Windows 11、macOS 等具体版本的视觉细节固化为业务组件规则；系统级标题栏、最小化和多窗口通信最终由真实客户端壳决定。

## 2. 五类交互载体

| 载体 | 适用场景 | 默认行为 | 不适用场景 |
| --- | --- | --- | --- |
| 模态弹框 Modal | 确认、警告、删除、覆盖、少量必填输入、需要立即阻断当前操作 | 遮罩当前页、锁定背景焦点、完成或取消后返回原位置 | 长表单、跨模块创建、需要参考主页面上下文的连续任务 |
| 锚点浮层 Popover | 快捷操作、轻量创建、筛选、菜单、单项选择 | 贴近触发点，点击外部或 Esc 关闭，不改变路由 | 多步骤、复杂校验、可能产生未保存草稿的任务 |
| 侧边抽屉 Drawer | 信息查看、上下文详情、关联操作、辅助配置 | 从右侧展开，保留主页面可见，抽屉内部独立滚动 | 必须并行查看多个模块、需要大画布或长时间编辑的任务 |
| 主窗口新页面 Page | 模块导航、业务工作台、可分享详情、需要历史记录的完整页面 | 更新主窗口 URL，支持前进/后退和刷新恢复 | 只是一次确认或必须与主页面并行完成的任务 |
| 独立任务窗口 Task Window | 跨模块创建/编辑、协作任务、复杂表单、需要完整任务工作面的操作 | 打开独立路由和任务窗口壳；Web 原型在同一应用视口内绘制窗口，真实客户端可映射为原生子窗口 | 简单确认、一次选择、无上下文的轻量操作 |

### 2.1 选择顺序

1. 是否是不可逆操作、确认或警告：使用模态弹框。
2. 是否是围绕一个触发点的短操作，且没有草稿保护需求：使用锚点浮层。
3. 是否需要保留当前列表/页面作为上下文，只做查看或关联操作：使用侧边抽屉。
4. 是否是模块级导航、工作台或可独立访问的详情：使用主窗口新页面。
5. 是否要在主窗口继续浏览的同时，完成跨模块、长表单或协作任务：使用独立子窗口。

不允许仅因为“内容放不下”就把弹框加宽；内容复杂度已经超过弹框职责时，应切换为抽屉、新页面或独立子窗口。

## 3. 通用交互规则

### 3.1 路由与状态

- 主窗口新页面与独立子窗口必须有可直接访问、可刷新恢复的规范 URL；Modal、Popover、Drawer 默认不单独占用一级路由。
- 路由只表达业务对象和动作，不把 `modal`、`drawer` 等临时视觉形式写进 URL。
- 入口携带的日期、时间、来源和对象 ID 可通过路由参数或查询参数传递；表单草稿、参与人列表等复杂状态不得全部塞入 URL。
- 刷新后若无法恢复完整草稿，应明确回到安全默认状态并提示，不得渲染空白窗口。

### 3.2 打开、关闭与焦点

- Modal 打开后焦点进入第一个有效操作，Tab 不得逃出弹框，Esc 仅在不会丢失数据时关闭。
- Popover 点击外部关闭；若包含正在输入的草稿，应先升级为 Modal/Drawer 或增加明确确认，不得静默丢失。
- Drawer 保留主页面视觉上下文，但背景区域在编辑态不得接受会破坏当前任务的操作。
- 新页面使用浏览器/客户端历史返回；任务窗口使用标题栏关闭，Web 原型关闭后回到来源页，不用浏览器新标签页或主窗口返回按钮伪装。
- 所有带表单的载体在关闭前检测脏数据；存在未保存内容时统一询问“放弃修改 / 继续编辑”。

### 3.3 反馈与异常

- 保存成功后明确反馈，并更新主窗口对应列表、详情和统计；不得只关闭载体而不说明结果。
- 保存失败时保留用户输入，错误信息靠近问题字段或出现在统一错误区。
- 登录失效时先保护草稿，再引导重新登录；不得直接清空独立窗口内容。
- 删除、清空、覆盖等高风险操作即使发生在 Drawer 或 Task Window 内，也必须再使用 Modal 确认。

## 4. 独立任务窗口行为规范

### 4.0 Web 原型与真实客户端的边界

- Web 原型默认采用“单浏览器页 + 客户端舞台 + 窗口组件”表达任务窗口，不调用 `window.open`，不让浏览器地址栏、标签页或浏览器外框成为产品交互的一部分。
- 客户端舞台可使用品牌氛围背景图，目的是让评审者看出窗口边界；背景图不得进入表单、时间轴和业务工作面，也不得成为业务信息的唯一载体。
- 任务窗口有独立 URL，打开时在当前应用内进入该 URL，并携带安全的 `returnTo`；关闭或提交完成后返回来源页。
- 真实客户端接入 Electron、Tauri 或供应商容器后，可把相同 URL 与 `TaskWindowShell` 内容映射为原生子窗口。原型阶段不得宣称已经具备原生多窗口、系统最小化或 IPC 能力。
- 区分标准：Modal 有背景遮罩、阻断当前窗口、尺寸较小且无独立路由；Task Window 有完整标题栏、独立 URL、任务工作面和固定操作区，不叠加黑色 Modal 遮罩。

### 4.1 窗口身份与重复打开

- Web 原型同一时刻只展示一个任务窗口；进入新任务前必须处理当前草稿，不创建浏览器弹窗或空白标签页。
- 真实客户端的重复聚焦与多窗口并发属于壳能力；接入前保留对象 ID 和规范 URL 作为窗口去重依据。
- 窗口标题使用“动作 + 对象”，例如“创建日程”“编辑日程”“预约会议”，不使用含糊的“新建”。
- 子窗口有独立规范 URL。日程首批规划路径：
  - 创建日程：`/pc_client/calendar/create`
  - 编辑日程：`/pc_client/calendar/events/:eventId/edit`
  - 预约会议：`/pc_client/meetings/create`
  - 编辑会议：`/pc_client/meetings/:meetingId/edit`

### 4.2 主子窗口联动

- 任务窗口提交后向共享 Store 写入结果；返回来源页时，日历、会议列表、会议室占用和数量状态读取同一份状态。
- 任务窗口取消或关闭不产生业务数据；有草稿时先确认是否放弃。
- Web 原型不得依赖 `window.opener`、跨标签页消息或浏览器弹窗授权。真实客户端 IPC 方案待技术框架确认。

### 4.3 尺寸与可用性

- 参考图为 `2880 × 1920` 像素，按 2 倍图推测逻辑画布约 `1440 × 960`；该值只用于原型验收参考，不作为正式客户端默认尺寸。
- 正式默认尺寸、最小尺寸、最大化/缩放能力、多显示器策略均待客户端技术确认。
- 在正式参数确认前，原型至少验证 `1440 × 900`、`1280 × 800` 和 `1024 × 720`；低于内容最小宽度时优先让内容区内部滚动，不压缩字号或遮挡底部操作。
- 窗口本身只允许一个主滚动关系；表单内容与时间轴可以分别独立滚动，但标题栏和底部操作栏固定。

## 5. 独立子窗口视觉规范

### 5.1 窗口壳

- 独立子窗口不显示客户端全局导航、模块侧栏、用户菜单或“打开的页面”导航；它只承载当前任务。
- 当前 Windows 原型使用右侧“最小化 / 最大化或还原 / 关闭”排列，标题和应用标识位于左侧；禁止出现 macOS 红黄绿交通灯。
- Web 原型的最小化按钮只作为壳能力占位并禁用；最大化/还原可以在舞台内模拟；关闭必须执行草稿保护并返回来源页。
- 标题栏使用中性浅灰表面与 `40px` 高度，业务品牌色仅用于应用标识和主操作，不把整条标题栏染成品牌色。
- 舞台背景图只出现在窗口外侧；窗口内正文工作面为白色或深色主题表面。背景图必须可替换，不能用图片模拟按钮、文本、阴影或窗口边框。

### 5.2 内容布局

- 默认采用“任务表单 + 上下文预览”双工作面：左侧完成输入，右侧提供与当前任务直接相关的时间、人员、冲突或资源上下文。
- 参考图左右比例约为 `58% : 42%`，两侧均为白色工作面，中间与窗口边缘露出底面背景；比例可随内容调整，不得机械套用到所有子窗口。
- 工作面圆角沿用客户端一级工作面 `16px`，工作面间距沿用 `8px` 基线；不在工作面内继续套大卡片。
- 左侧表单正文独立滚动，底部“取消 + 主操作”固定；主操作使用品牌主色 `#B82971` 对应语义令牌，取消使用白底边框按钮。
- 右侧上下文区的工具栏、日期切换和参与人摘要固定，时间轴或列表独立滚动。

### 5.3 表单与上下文联动

- 表单顶部先展示任务归属和当前主题摘要，再进入字段。
- 相关字段可使用两列，例如“日期 + 时间”“重复 + 提醒”“会议室 + 地点”；长文本和参与人保持通栏。
- 日期、时间、参与人、会议室变化后，右侧忙闲/冲突视图必须同步更新；右侧不是装饰占位。
- 右侧冲突区至少区分可用、忙碌和当前选择三个状态，并提供可理解的时间刻度与时区。
- 房间选择、通讯录批量选择、自定义重复等属于子任务，可在独立窗口内部继续使用 Modal；不得再打开第二层独立子窗口形成窗口链。

## 6. 创建日程目标方案

### 6.1 目标形态

- “创建日程”从当前居中弹框迁移为独立子窗口，规范路径为 `/pc_client/calendar/create`。
- “预约会议”与“编辑日程/会议”复用同一套 Task Window 壳与表单核心，不再在 `Calendar.tsx`、`MeetingScheduleDialog.tsx` 和会议模块中维护多套重复表单。
- 左侧表单保留现有能力：主题、参与人、日期、开始/结束时间、重复、提醒、会议方式、会议室、地点、描述和附件。
- 右侧按参考图展示当前日期、时区、参与人和时间轴；当参与人或会议室变化时更新忙闲和冲突状态。
- 底部操作固定；提交成功后关闭或进入结果态，并同步主窗口日历、会议列表与会议室占用。

### 6.2 入口统一

以下入口必须打开同一个独立窗口实现，不再各自维护弹框：

1. 日历工具栏“创建日程”。
2. 日历时间格拖选后的创建入口。
3. 如意会议“预约会议”。
4. 会议室视图从空闲时间段发起预约。
5. 会议详情中的“修改会议/日程”。
6. 如意助手返回的“前往日历手动创建”等跨模块入口。

入口只负责提供来源与预填参数；字段校验、保存、忙闲校验和草稿保护由统一窗口组件负责。

### 6.3 内部弹框保留范围

- 通讯录批量选择：Modal。
- 会议室搜索与闲忙筛选：Modal。
- 自定义重复：Modal。
- 放弃未保存修改：确认 Modal。
- 外部会议方式选项、轻量菜单：Popover。

- 改造 `Calendar.tsx`、`Meetings.tsx`、`MeetingRoomView.tsx`、`MeetingDetailDialog.tsx` 的入口，删除完成迁移后的重复弹框状态。
- 迁移需求模式中的“创建日程/预约会议弹框”旧表述与锚点；必须通过本机需求编辑器维护，不直接手改 `docs/PROTOTYPE_REQUIREMENTS.md`。

| 现有功能 | 当前形态 | 建议目标 | 说明 |

### P2：沉淀共享组件与自动化检查

- 统一 `Modal`、`Popover`、`Drawer`、`TaskWindowShell` 的焦点、Esc、滚动锁定、脏数据保护和深色模式行为，不新增大型 UI 依赖。
- 为独立窗口增加路由直达、重复打开、提交同步、关闭保护、登录失效与刷新恢复检查。
- 浏览器验证“同一应用页进入任务窗口舞台、关闭返回来源页”的原型行为；原生最小化、真正多窗口、IPC 和主窗口关闭联动必须在客户端壳环境另行验收。

## 8. 验收清单

- 开发前已明确本功能使用 Modal、Popover、Drawer、Page 或 Task Window，并记录理由。
- 创建日程所有入口都进入同一规范 URL 和同一实现。
- 独立窗口不出现客户端全局导航，不被计入主窗口“打开的页面”。
- 表单与右侧上下文真实联动；日期、时间、参与人和会议室变化能反映冲突状态。
- 标题栏、表单正文、右侧时间轴和底部操作栏的滚动关系正确。
- 打开任务窗口不会创建浏览器弹窗或空白标签页；URL 与来源返回路径正确。
- 未保存关闭有保护，保存失败不丢草稿，保存成功能同步主窗口。
- 关键尺寸无重叠、无按钮遮挡、无多余浏览器级滚动条。
- 通过 `npm.cmd run check`、`npm.cmd run build` 与关键入口浏览器回归。
