# 参考基线与证据等级

本文件定义员工端页面和组件规范的权威来源。所有新增或改造任务必须先说明使用了哪些参考文件；不能只写“参照截图”。

## 1. 证据等级

| 等级 | 来源 | 用途 |
| --- | --- | --- |
| A | `docs/references/spec-*` 组件规范图 | 颜色、字阶、按钮、导航、空状态、录入字段等长期设计规则 |
| B | `docs/references/page-*` 真实页面截图 | 页面信息架构、内容顺序、密度、品牌素材、组件组合和视觉氛围 |
| C | `docs/*.md` 中已经确认的产品规则 | 业务术语、导航关系、状态闭环和实现边界 |
| D | `src/` 当前实现 | 现状、技术约束和迁移差距，不作为目标视觉依据 |

冲突处理：A 级决定组件与 Token，B 级决定页面结构与组合，C 级补充业务行为。D 级只能记录差距。截图中的姓名、日期、数量和金额默认是演示数据，不自动成为长期业务口径。

## 3. 页面接受标准

### 首页

- 必须呈现企业门户而不是通用社交流。
- 顶部品牌区、待办入口、快捷应用、公文信息和内容运营区块的顺序与 `page-home.jpg` 一致。
- 长页面使用自然滚动；底部导航固定，不能遮挡最后一个内容区块。
- 品牌图片可以替换为经确认的新素材，但不能用“Banner占位”作为完成状态。
- 待办数量为图标右上的品牌粉红底白字角标气泡，不显示为大号数字；无数量项不留横杠或空角标。
- 快捷应用前五项复用工作台 `ws-00..ws-04` 资源；“全部”位于第二行第一列，点击（含搜索结果点击）必须进入 `/workspace`。
- i快讯为白色圆角资讯卡（左品牌标识 + 右 DOM 标题）；企业信息四页签在 360/375/480px 均单行；精品推荐为四张独立白底卡。
- 如意助手固定在应用画布水平中间，文案“问问您的如意助手”，本地人物头像；首屏背景不透明，下滑仅背景半透明，回顶恢复实底；需避让底栏与最后一项内容。

### 日程与任务

- “日程/任务”是页面内部一级标签，“待处理/已处理”只在任务标签下出现。
- 日历包含公历、农历或节气、事件点和“今天”操作。
- 任务必须同时覆盖空状态和已处理列表状态。非空数组却没有列表渲染视为阻断缺陷。
- 浮动新增按钮使用品牌辅助金色，必须按应用画布定位并避让底部导航与安全区。

### 工作台

- 搜索应实际过滤或明确进入搜索结果，不能只有输入外观。
- “我的工作台”支持编辑入口；推荐应用和综合服务是不同信息层级。
- 综合服务按稳定四列网格展示，图标使用同一黑色线稿加品牌粉点缀语言。

### 我的

- 人员身份卡和航空品牌背景是首屏识别重点。
- 薪酬、打卡、福利和钱包属于四个高优先级入口。
- 菜单必须按业务分组，不把全部操作塞进一个通用列表卡。
- **退出操作由顶部右侧退出图标承接并打开页面内确认层；不实现左侧返回，也不实现页面底部独立“退出账号”按钮**（用户 2026-11-10 明确覆盖，优先于 `page-profile.jpg` 旧截图；已落到 `Profile.vue`）。删除底部按钮后末菜单组与底栏之间不得留下大块空洞。
- 背景资源只含天空与飞机，不得烘焙退出门、状态栏、资料卡或任何 UI；480px `object-fit: cover` 下同样必须干净。

### 消息

消息页登记为**结构性基线**（见 §2「消息结构性基线」），不设 `page-message*` 截图（用户 2026-11-11 确认 Q2，覆盖本文件旧「视觉待补充 / 不得升级为正式基线」结论）。验收口径：

- 结构与信息架构按 §2 结构性清单逐区块对照（区块顺序、层级、导航关系、状态口径）。
- 颜色、字阶、按钮、导航、空态、录入字段、图标一律以 `DESIGN_SYSTEM.md` 与 `spec-button` / `spec-navbar` / `spec-empty` / `spec-colors` / `spec-field` / `spec-typography` 为准。
- 360px 主验收需逐个 `spec-*` 留下对照结论；**不得声称存在消息页截图基线，也不得以缺截图为由跳过视觉验收**。

## 4. 视觉验收方式

- 主验收宽度为 360 CSS px，同时检查 375px 和 480px。
- 消息页 360px 主验收的逐区块对照对象为「§2 消息结构性基线清单 + `spec-*` 六张组件规范图」；不引用 `page-message.jpg`（Q2）。
- 页面截图按区块对比：结构顺序、水平对齐、密度、字体层级、颜色、圆角、图标、固定元素和安全区。
- 页面截图包含系统状态栏时，Web 原型不要求伪造系统状态栏；比较从应用内容区开始。
- 动态日期、头像、姓名和业务数字可使用明确标注的模拟数据，但格式、层级和占位尺寸必须一致。
- 没有正式素材时使用尺寸正确的本地占位，并在 `tasks/CURRENT.md` 标记待替换；不能使用不稳定的远程图片冒充完成。

## 5. 参考图变更流程

新增或替换参考图时：

1. 使用语义化文件名放入 `docs/references/`。
2. 更新本文件的映射和页面接受标准。
3. 记录旧基线是否废弃，以及受影响路由和组件。
4. 不静默覆盖同名文件；需要保留历史时使用日期或版本后缀。
