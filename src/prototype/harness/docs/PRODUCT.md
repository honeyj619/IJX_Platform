# i吉祥原型产品基线

## 1. 项目定位

i吉祥是面向企业员工的统一协同入口，整合企业门户、日程与任务、业务应用、消息协作、个人服务和如意助手。本仓库用于产品评审、方案演示、领导汇报和研发交接，不承诺生产级数据、权限、安全、性能或可用性。

原型的首要目标是准确表达产品结构和关键操作，而不是快速堆出可点击的通用页面。

## 2. 目标用户

| 用户 | 核心诉求 |
| --- | --- |
| 普通员工 | 获取企业信息、处理待办、访问应用、查看日程、沟通协作、使用员工服务 |
| 管理人员 | 获取团队信息、跟进任务、查看汇报和目标 |
| 平台运营管理员 | 配置门户内容、应用入口、展示范围和员工视角 |
| 产品、设计、研发人员 | 验证页面、交互、业务规则和跨模块状态 |

## 3. 员工端信息架构

固定五个一级入口：

| 路由 | 入口 | 产品职责 | 页面基线 |
| --- | --- | --- | --- |
| `/` | 首页 | 企业门户、工作入口、内容运营、福利与推荐 | `docs/references/page-home.jpg` |
| `/schedule` | 日程 | 日历、任务、状态筛选和新增入口 | `page-schedule-calendar.jpg`、`page-schedule-empty.jpg`、`page-schedule-completed.jpg` |
| `/workspace` | 工作台 | 应用搜索、个人工作台、推荐和综合服务 | `page-workspace.jpg` |
| `/message` | 消息 | 会话、业务消息和关联事项 | **结构性基线（本文 §4 + `REFERENCE_BASELINES.md §2`） + `spec-*` 组件规范**；不设 `page-message*` 截图（Q2） |
| `/profile` | 我的 | 人员身份、员工服务、钱包和账户操作 | `page-profile.jpg` |

一级页面通过固定底部导航切换。详情、编辑、搜索结果和业务办理属于二级页面，必须提供明确返回路径，不能增加新的底部入口代替层级设计。

## 4. 页面产品结构

### 首页

首页是高密度企业门户，目标结构为：

1. 城市、快捷服务搜索、扫码或快捷操作、消息提醒。
2. 未读公文、待办流程、今日日程、我的课程等高频状态入口。数量由同一份数据派生，以品牌粉红底白字角标气泡显示在图标右上；无数量时不显示横杠、0 或空角标。
3. 吉祥航空品牌头图。
4. 会议室、通讯录、流程中心、员工活动室、公司值班等快捷应用和“全部”。前五项复用工作台同族图标；“全部”位于第二行第一列并进入工作台 `/workspace`。
5. i快讯白色圆角资讯卡（左侧品牌标识 + 右侧 DOM 标题）、战略规划等运营横幅。
6. 公司文件、会议纪要、通知公告等信息列表，四个页签在 360/375/480px 下均保持单行。
7. 关于吉祥、福利中心、如意商城、精品推荐等内容区块；精品推荐为 N1 背景上的四张独立白底圆角卡。
8. 如意助手入口和固定底部导航。助手为应用画布水平居中的白色胶囊，文案“问问您的如意助手”，左侧本地人物头像；首屏不透明，滚动后半透明，回到顶部恢复实底，由 IntersectionObserver 低成本切换。

首页不是“Banner + 动态流 + 通知”的通用模板。区块可按后续需求增减，但门户、工作入口、企业信息和员工服务四类职责必须保留。

### 日程与任务

- 页面内部包含“日程”和“任务”两个标签。
- 日程状态展示月份、今天、周视图、公历、农历或节气、事件点及选中日期内容。
- 任务状态包含“待处理”和“已处理”筛选，并展示数量。
- 待处理为 0 时展示空状态；已处理非 0 时必须展示任务列表。
- 浮动新增入口根据当前标签创建日程或任务，并提供可见反馈。
- 模拟日期必须由同一份年月数据派生，不能出现固定月份与设备日期混用造成矛盾。

### 工作台

- 搜索范围为应用和服务，输入后必须产生筛选结果或进入搜索结果页。
- “我的工作台”展示用户固定的高频应用，并提供编辑入口。
- “推荐应用”是平台推荐，不与个人固定应用混为一组。
- “综合服务”承载全量服务入口，按业务顺序形成稳定网格。
- 应用点击必须进入页面、展示详情或明确标记“暂未开放”，不能弹出模拟成功提示。

### 消息

用户 2026-11-11 确认 Q2 / Q3 / Q5。以下为权威实现 `src/prototype/views/Message.vue`、`views/message/*` 与 `src/prototype/im/` 的长期业务口径，均可由代码验证。页面**不设截图基线**，视觉以 `DESIGN_SYSTEM.md` + `spec-*` 为准（结构性基线见 `REFERENCE_BASELINES.md §2`）。

#### 消息分类

- **会话 5 类**：`single`（单聊）、`group`（群聊）、`service-inbox`（员工服务收件箱）、`service-ticket`（服务咨询子会话）、`im-app`（消息应用）。
- **消息 13 类**：文本、图片、视频、语音、文件、名片、图文、表情、系统消息、通话记录、投票、接龙、话题；另支持引用、回应、置顶、逐条与合并转发、定时消息、阅后即焚等能力标记。
- **筛选**：「全部 / 未读 / @消息」三种，列表内一级筛选，不改变五栏导航；应用消息与服务号纳入统一未读数与搜索。
- 隐藏会话、服务咨询子会话、文件传输助手不在会话列表展示。

#### 已读规则

- 进入会话即清零 `session.unread`；**未读角标由 `session.unread` 单一派生**，不维护重复计数。
- `@消息` 仅群聊参与，且**仅检查当前未读区间**；`@所有人` 视为提到当前用户；已读后从 @ 筛选结果消失。

#### 详情行为

- 消息操作：引用 / 复制 / 回应 / 撤回 / 重新编辑 / 删除 / 置顶 / 逐条转发 / 合并转发，全部写回 Store。
- 搜索结果携带 `messageId`，进入会话后滚动定位并短暂高亮。
- 群资料改名实时同步会话标题与搜索结果；清空聊天记录同步清除列表预览、时间与排序。
- 草稿、置顶、星标、免打扰、会话与消息状态持久化于 `ijx-vue-im-store-v1`（`zustand/vanilla + persist`，含 `version` / `migrate` / `partialize`），刷新可恢复，演示数据可一键恢复。

#### 未实现能力（Q5：统一「暂未开放」）

- 真实摄像头扫一扫、语音 / 视频通话媒体流、员工服务号真实后端、消息应用真实菜单接口**统一标注「暂未开放」**；不得把 Mock 演示流程当作完成状态，相关页面需给出明确提示与返回路径。
- **代码落地（2026-11-11 P2-1）**：扫一扫页 / 通话面板 / 联系人语音视频 / 服务咨询入口 / 应用菜单 URL 分支 / 群文件真实存储均已加「暂未开放」标识；原型流程示例保留但标注「不代表功能已开放」，完成态文案（「扫描完成」「已生成通话记录」「演示链接」）已移除。
- 演示数据仅用于产品评审，不代表生产级数据、权限、安全或可用性。

#### 最低闭环

收到模拟消息 -> 打开会话或关联事项 -> 完成操作（含处理中反馈）-> 消息、事项状态与列表预览同步 -> 返回或继续。

### 我的

- 首屏展示航空品牌背景与人员身份卡（头像、姓名、性别、职位、部门）。
- 顶部操作区**只有右侧两个同族线稿图标，顺序为退出、设置**；无左侧返回按钮。退出为门形图标并打开页面内退出确认层，设置为齿轮图标并给出“暂未开放”轻提示。
- 展示入职日期和司龄纪念信息。
- 薪酬、打卡、福利、钱包是高优先级员工服务，使用黑色线稿加品牌粉色点缀图标，无方块底。
- 可继续展示 Wi-Fi、钱包余额与付款码、邮箱、学习、IT 资源、帮助反馈、账户安全。
- **不设页面底部独立“退出账号”按钮**；退出操作统一由顶部退出图标承接（用户 2026-11-10 明确覆盖规则，优先于 `page-profile.jpg` 旧截图）。
- 菜单按业务关系分组，不能用任务统计替代员工服务结构。

## 5. 核心演示故事线

员工端主线：

进入首页 -> 查看个性化信息或待办 -> 从消息、日程或应用入口进入事项 -> 查看详情并处理 -> 获得结果 -> 返回一级页面后看到数量或状态同步。

如意助手主线：

输入问题 -> 展示处理中 -> 返回回答或业务卡片 -> 查看来源或进入业务页面 -> 失败时可重试。

管理端主线：

修改配置 -> 校验 -> 预览 -> 保存草稿 -> 发布 -> 切换员工视角 -> 验证生效结果。

## 6. 核心场景最低闭环

| 场景 | 最低闭环 |
| --- | --- |
| 门户与应用导航 | 打开入口 -> 展示目标内容或明确未开放 -> 可以返回 |
| 日程/任务 | 查看列表 -> 进入详情或新增 -> 提交 -> 列表和数量同步 |
| 消息协同 | 打开消息 -> 进入会话或事项 -> 完成操作 -> 已读或事项状态同步 |
| 如意助手 | 输入 -> 处理中 -> 回答/卡片 -> 来源/跳转 -> 失败重试 |
| 门户配置 | 修改 -> 预览 -> 保存 -> 发布 -> 员工视角验证 |

`alert()` 只允许用于非核心、明确标注为临时占位的入口，不能作为核心闭环的验收结果。

## 7. 数据规则

- 默认使用本地模拟数据，并明确它不是生产数据。
- 人员、应用、任务、消息等跨页面对象集中维护，使用稳定标识。
- 搜索、筛选、数量和状态由同一份数据派生，不维护重复计数。
- 动态日期与固定演示日期只能选择一种策略；策略记录在当前任务中。
- 核心演示数据需支持恢复初始状态。
- 不使用真实敏感信息、令牌、密钥或生产接口。
