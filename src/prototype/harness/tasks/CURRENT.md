# 当前任务

状态：已完成，待产品确认

## 目标

优化 App 端“我的-帮助与反馈”页面，建立清晰的提交与进度查询双路径，并保留自动关联最近业务页面的能力。

## 范围与影响文件

- 新增 `/profile/feedback` 二级路由与反馈页面，隐藏底部五栏导航。
- “我的”页面的帮助与反馈入口改为真实导航。
- App 壳层记录最近访问的非个人中心业务页面，供反馈表单反显。
- 更新跨端路由合同和页面冒烟清单。
- 反馈继续写入现有 `ijx-feedback-records-v1` 本地模拟数据，不新增后端。

## 设计差距与本轮处理

- 旧实现未进入当前权威分支，“我的”入口仍显示暂未开放，本轮补齐正式二级页。
- 将重复的“反馈当前页面”卡与表单关联区合并，减少首屏层级。
- 使用“我要反馈 / 我的反馈”双标签，避免表单与长列表同时堆叠。
- 主按钮吸底并避让安全区；反馈详情使用底部抽屉。
- 统一品牌玫红、N 系中性色、T 系字阶和 12px 卡片圆角。

## 状态覆盖

- 默认：关联最近业务页面、默认选中“功能异常”。
- 选中：反馈类型和双标签切换。
- 禁用：未填写问题描述时提交按钮禁用。
- 加载：提交按钮显示“正在提交”。
- 错误：空内容就近提示，超限附件给出轻提示。
- 空：没有个人反馈时显示空状态及提交入口。
- 成功：生成反馈编号、切换到“我的反馈”并显示成功提示。
- 详情：反馈状态、内容、页面和时间线底部抽屉。

## 验收标准

- 从日程进入“我的”再打开帮助与反馈时，相关页面反显 `/schedule`，而不是 `/profile`。
- 表单提交后只新增一条记录，并在“我的反馈”首项显示。
- 360px、375px、480px 下无横向滚动、遮挡和不可点击末项。
- 200% 文本缩放时核心表单、提交按钮和详情仍可访问。
- `npm.cmd run check`、`git diff --check` 通过；浏览器关键流程无页面错误。
