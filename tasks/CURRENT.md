## 范围

在 `/admin/versions` 的 android、iOS、macOS、Windows 四个页签中，点击“添加”打开统一结构的新增弹框：

- 四端共用一个弹框组件，字段、排版、校验反馈和提交行为完全一致；当前页签决定新增记录所属端，弹框内无端类型选择器。
- 仅标题、安装包扩展名、安装包类型、默认系统说明按端配置（`versionCreatePlatformConfig` 驱动，未复制四份 JSX）。
- 字段顺序：安装包、Logo、版本号、构建号、强制更新、适用范围、描述、修复内容。
- 原有“编辑版本配置”弹框、列表、筛选、分页等既有交互不在本次改造范围内，保持可用。
- 原型阶段不接真实上传服务：不伪造后端接口，不把安装包转 Base64，不把 File 对象塞入长期记录，不伪造下载地址。

## 完成项

- 新建 `src/components/admin/VersionCreateDialog.tsx`：承载新增弹框 UI、临时表单状态、文件/图片校验、错误展示、关闭清理与 `platformConfig`。
  - 安装包：必填；扩展名校验大小写不敏感（`.APK` 可识别），不依赖浏览器 `accept`；错误显示在字段下方；已选文件显示文件名/大小，可替换/移除。
  - Logo：必填；仅接受 PNG 且自然尺寸严格为 48 × 48 像素（读取 naturalWidth/Height 校验）；错误文件不进入有效表单状态；预览 object URL 在替换、关闭、组件销毁时释放（异步调度 revoke，避免中断加载中的 blob 请求）。
  - 版本号：沿用现有非空校验（无红星视觉），去除首尾空格；同端内版本号重复时阻止提交（跨端允许，iOS 已有 3.3.1 时 android 可新增 3.3.1）。
  - 构建号：只读，按 `YYYYMMDD + 当日三位序号` 生成（当日实测 20261110001 → 新增后 20261110002），结合现有记录计算当日最大序号，跨端共用当日序号（与既有模拟数据 20260818001/002 语义一致）。
  - 强制更新：可访问 Switch（`role="switch"` + `aria-checked` + `aria-label`），默认“否”，保存布尔值。
  - 适用范围：非必填单选，选项为“全员”加现有用户组（getUserGroups 实时读取），值使用稳定 ID。
  - 提交校验：首次点击“确定”统一触发；失败保留输入并聚焦第一个错误字段；成功在当前端列表顶部新增“草稿”记录、回到第一页、显示“XX版本已添加”轻提示。
  - 关闭行为：关闭图标、取消、遮罩点击统一关闭；Esc 使用 document 级监听（焦点不在弹框内，如文件上传控件，也可关闭）；重新打开无残留。
  - 可访问性：`role="dialog"`、`aria-modal`、标题关联、图标按钮 aria-label、`role="alert"` 错误提示；file input 使用 sr-only（屏幕阅读器可感知）。
  - 布局：约 800px 宽（`w-full max-w-[800px]`，小视口 `calc(100vw - 32px)`），`max-h-[calc(100vh-64px)]`，Header / 可滚动 Body / Footer 三段结构。
- 修改 `src/pages/Admin.tsx`：`VersionRecord` 增加可选元数据字段（scopeId/scopeLabel/packageFileName/packageSizeLabel/packageExt/logoFileName）；“添加”入口改为打开新弹框；新增 `handleCreateSubmit` 写入列表并回到第一页；既有编辑/删除入口未动。
- 更新 `docs/ADMIN_UI_GUIDELINES.md`：新增 8.1“新增版本弹框（四端共用）”规范（字段、端差异、滚动、上传校验、原型边界）。
